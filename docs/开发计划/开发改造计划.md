# 开发改造计划

本计划安排办公IT支持与协同排障目标的实现顺序及完成条件。业务、权限和停止边界见[系统设计](../设计/系统设计.md)，31张自有表及约束见[数据库设计](../设计/数据库设计.md)，协议见[接口约定](../设计/接口约定.md)，文件职责见[项目结构](../设计/项目结构.md)。全部阶段共同交付同一个最终系统，不是另设功能版本；阶段不能省略已确定的权限、失败和恢复合同。

当前P1–P6人工链、现场、知识和私有排障已实现并完成分项隔离业务验收，P7工作台与知识反馈处置、P8本地可复现实验已交付，证据见[P0–P3实施与验收](P0-P3实施与验收.md)、[P4–P6实施与验收](P4-P6实施与验收.md)和[P7–P8本地交付与验收](P7-P8本地交付与验收.md)。P0采用[四类官方资料候选场景](P0场景与验收边界.md)，用户确认无打印机及Microsoft 365环境，设备实测明确未验证；生产级Broker回查耗尽、完整ELK故障矩阵及部署恢复仍未验收。31表435字段沿增量链维护，不改写已应用迁移；P9镜像与部署按本地交付范围延期。

## 1. 总体顺序

先验证支持场景与证据，再按业务切片实现。每阶段同步页面、接口、权限、状态、迁移和必要测试，不批量生成空CRUD，不先迁移整个通用Agent运行时。

| 阶段 | 业务结果 | 完成证据 |
| --- | --- | --- |
| P0 | 场景、工程合同、目标迁移及外部风险明确 | 四类支持样例、数据盘点/迁移矩阵、协议、关键依赖隔离实验 |
| P1 | 管理员开通组织账号及服务人员范围 | 登录、改密、CSRF、内部核验、撤权及最后管理员保护 |
| P2 | 客户在支持范围内直接提交问题 | 服务目录/资格及审计、可选设备、待分类及原键回执 |
| P3 | 人工处理与客户确认闭环 | 分类/环境更新、接单转派、处理/转介、确认/超时结单、时间线及通知 |
| P4 | 必要现场服务 | 工单地点、资格、区域时段、事务确认/取消及真实履约 |
| P5 | 有权且适用的PDF/文本知识可发布检索 | 原件版本、适用规则、可靠索引、真实定位、双索引及撤权 |
| P6 | 客户自助与技术人员辅助共同服务问题处理 | 带来源事实、跨轮环境复核、规则/模型分流、有界工具、逐次调用、版本及人工草稿采用 |
| P7 | 工作台及管理处置完整 | 组合角色、私有会话、反馈共享限制、检索/事务异常处置 |
| P8 | 业务正确性及Agent效果可复现 | 单次RAG/固定流程/动态诊断对照、故障与失败分布、成本延迟 |
| P9 | 独立交付与恢复 | 镜像及最小上传集合、真实联调、联合备份和隔离恢复 |

人工链不依赖AI/知识、模型额度或PDF解析。AI能力限定为有资料和验证的题型，不能由工单可受理范围推断模型能诊断全部问题。

## 2. P0 场景、工程与迁移风险

为终端、打印、网络连接及指定软件各准备明确支持条件、操作者、输入和停止边界，确定真实可取得的手册、规程、软件环境及设备验证条件。先用少量人工核对案例确认信息足够支撑排障，涵盖反馈改变分支、未知条件和范围外交接；没有设备实测只报告用户反馈或标注评价，不编造客户落地。

盘点四库真实迁移历史及已存在数据，按[目标增量迁移](../sql/README.md#6-办公it支持目标的增量迁移)制定服务项目/旧设备资格、适用规则、旧会话/引用/草稿及结单历史映射。空基线的V2/0002及独占MySQL验证已完成；非空旧库继续按映射矩阵单独实施。禁止改写已应用V1/0001/V2/0002或直接删库重建。

维护已交付的common/api基础合同、普通JSON成功0/系统1及错误边界、32位ID、UTC、分页、生成包、依赖方向和本机配置打包排除。身份/业务RPC、MQ v2及服务项目管理白名单按目标同步实际消费者和CI对应集合，不生成空方法或空进程；当前公共.proto生成通过不表示业务RPC已联调。

高风险隔离实验包括MySQL JSON/CHECK/生成列/复合FK/锁序、PDF中文扫描及Markdown真实锚点行区间、百炼向量与tool-call合同、Qdrant过滤/快照、ES两路一致性、TLS RPC/错误/Deadline/原件流。MQ验证半消息→本地COMMITTED→Broker确认/回查→AI短事务落库再ACK→worker，覆盖未知/重启/准备过期/ACK丢失/取消先到，v2内容格式及摘要固定。已有v1业务须先保留原摘要兼容并登记退出条件。

Redisson锁/watchdog、Sentinel Reactive与实际RPC生命周期/Nacos规则、XXL注册/触发/回调和跨语言Zipkin也分别验证。一次性脚本和证据放仓库.local所属任务，不写系统临时目录。风险未验证不阻断无关人工链，但不能以替身完成知识/AI验收。

## 3. P1 身份与人员范围

维护组织、账号、角色及客户人员范围和审计，安装所属Session表。初始化唯一服务商及首名管理员，无默认口令，重复不覆盖；所有最后管理员保护使用同一串行化事务。页面随登录同步账号及范围管理。

验证Session轮换、首次/重置改密、CSRF、authVersion撤权、伪造身份头、跨客户、组织调动及历史读取。身份事实由user维护，客户服务开通归ticket，不能把二者混成一份全权授权。Feign/HTTP和gRPC适配同一用例，服务凭据/TLS失败不误报用户退出。

按既定职责接Nacos、Redis防刷、Sentinel及日志/追踪，配置隔离及生产文档关闭分别验收。网关不承担资源权限，前端菜单不证明授权。

## 4. P2 支持范围与问题提交

实现四类it_service_item目录、单id的it_service_entitlement资格区间、it_service_event不可变变更历史及必要型号/设备维护。资格业务唯一键为客户/项目，日期字段为starts_on/ends_on；不对生命周期实体套复合主键通用CRUD。全局目录由系统管理员维护，范围内客服维护客户资格；所有写动作带clientActionId，已有行另带版本及原因，和事件同事务，暂停恢复沿用原id；日期首尾有效、停用/暂停阻止新请求，旧履约保留。先确认旧数据资格映射，不将设备最晚到期自动升级成全部客户权益。

交付我的支持范围、固定环境表单、可选设备、直接提交、工单详情及原请求查询。允许有有效服务的客户“不确定”提交待分类，只承诺分流；明确项目核验目标开通，设备可空、非空须同客户且可新增关联。保存受理范围、可选资产、环境及人工确认交接快照。

验证未开通/过期、未知类别、设备跨客户/退役、同键重放/异义、响应未知及AI故障直接提单。回执先于新资格检查，sourceDraftId预留语义在真实草稿消费者接入时完成，不用空ValidateDraft假装成功。

## 5. P3 人工处理与确认

完成客服队列、待分类/超期待办、接单/分派/转派、环境更新、补充、公开/内部记录及通知。分类进新项目重核资格，固定工单客户/提交人，记录CONTEXT_UPDATED和变更原因，版本变化不能覆盖已有输入。

resolutionType区分RESTORED/GUIDANCE/REFERRED，转介给原因和去向；未分类仅允许转介结果。closureReason区分客户确认与72小时未反馈结单；不把超时当作修复。客户退回重建本轮处理期限，旧事件保留。

XXL有界触发ticket期限扫描，接单自行补记已超期，停机后补扫。工单、事件和通知同事务，验证双人接单、处理人撤权、版本/原动作键、转派竞争、超时结单/退回及通知权限。工作台概况不授予正文权限，也不将全部CLOSED统计为恢复成功。

## 6. P4 现场服务

现场是人工处理分支。已分类、受理项目支持现场、区域地点有效后开放资格，不要求绑定设备。地点以工单为权威，预约按当时工单地址快照，设备后续变更不回写。修改工单现场信息、解决/取消或撤回资格前结束活动预约。

交付人工核对出勤的时段发布、申请、原键查询、取消及实际履约。固定工单→预约→时段锁序，取得全部锁后另查UTC决策时间；容量、预约、事件及通知同事务。验证约满、关停、双请求、取消/履约竞争、只回补一次及未知响应，不接Redis库存/MQ或虚构PENDING。

## 7. P5 知识原件、适用与可靠索引

支持PDF及UTF-8 Markdown私有原件，字节摘要/OSS精确版本、同请求互斥及唯一回执共用同一上传机制。文本编辑以Markdown原件提交，保留真实锚点和行区间，不伪造页码；PDF使用MinerU、Markdown本地确定性解析，不创建远端任务。

修订至少一条项目规则，可选型号、系统/软件名称版本精确限定；未知不能作为匹配，规则只DRAFT修改，发布后固定。客户/服务人员受众分开。规程包含前置、检查、反馈、风险与停止条件，不执行内嵌脚本；脱敏案例不自动共享原工单。

实现RocketMQ事务SUBMIT/CANCEL v2、准备/回查/过期收敛、AI receiver短事务提交后ACK和worker令牌领取。页面分别显示本地提交、AI受理、执行及发布，未知不换jobId，不建设outbox/自动发送扫描器/HTTP提交旁路。验证半消息未知、二次确认丢失、回查/重启/耗尽、迟到确认、取消乱序、ACK丢失、DLQ和原指令受控重放。

原件流核对总量/最终RPC/SHA，完整切片一次固定，ES/Qdrant按稳定ID写入并逐路验证后才能发布。PDF/Markdown定位、适用条件、两路失败、旧worker、撤权、锁丢失、OSS未知/孤立对象及新修订替换真实联调。发布必须来源复核，不以索引成功替代内容审核。

## 8. P6 双侧辅助排障与人工动作草稿

先打通授权检索和单次RAG基线，再建立客户自助与工单内技术私有会话。保留单一MySQL受理/worker执行权，不直接依赖通用本地Agent包，不运行SQLite宿主或第二套Scheduler。选择性迁移上下文预算、工具合同、取消边界、用量归一化及对应行为测试，工具换成领域只读能力。

实现来源化诊断事实、版本化更正/撤回、跨轮待答项及有界工具循环。用户反馈、人工记录、工具观测和模型假设分开，建议不写为已执行。澄清结束本轮，回复新建generation；事实修改在无活跃轮时进行，取消保留输入且不提交旧输出。技术工单版本变化记CONTEXT_CHANGED，不自动重跑。

逐次模型请求/重试先登记，工具结果及实际上下文分别持久化，摘要/历史依赖的所有来源可回查；用量/费用未知不填0，不保存隐藏思维链。交付前核验全部来源及执行令牌，任何受限来源阻止相关正文/摘录/事实摘要/草稿泄漏。

交付可读来源、事实更正、阶段/工具流、历史、取消及原键查询。CREATE_TICKET使用客户确认事实模板；ADD_RECORD/RESOLVE_TICKET使用源运行已有校验结果。人编辑确认后经ticket原动作采用，校验用途/目标/期限/工单版本和当前处理关系，sourceDraftId唯一且不在AI存第二份消费事实。验证双人采用、旧版本、重复动作、草稿过期和响应未知。

技术人员不能直接读取客户私有会话或前任助手；交接靠正式事实。技术无帮助反馈为RECORDED，不进入无人可处理的PENDING队列，也不共享给知识管理员；客户自助反馈需明确许可及全部来源有权。完成反馈分支改变检索/下一检查、不重复已执行项、事实矛盾/错误版本、风险/预算停止及人工交接的真实示例。

## 9. P7 工作台与管理整合（已交付）

整合客户、客服、技术和管理页面。知识管理员可分页处置客户显式共享反馈；展开前复核会话、来源和当前授权，处理按行版本竞争。检索诊断与排障复用同一授权/匹配合同，索引回查及消费异常继续通过既有知识管理入口受控处置。组合角色不自动叠加正文权限，技术反馈仅脱敏聚合，通知缓存不展开撤权内容。实现和验证见[P7–P8本地交付与验收](P7-P8本地交付与验收.md)。

## 10. P8 评估与故障实验（本地范围已交付）

固定语料、题集、来源版本、模型、空间、Prompt和预算。先比较关键词/向量/融合，再在同可访问资料/工具条件下比较单次RAG、固定规程和动态诊断；在线取证带来的收益单列，不全部归因于Agent循环。开发题与评价题按故障变体隔离，隐藏答案不进入模型。

评价适用条件、必要澄清、事实保持、重复检查、引用支持、正确停止、交接完整、成本和延迟。允许多条合理路径，人工核对事实与结论，模型裁判仅辅助。现有隔离证据覆盖反馈改变分支、风险停止、错误版本切换、调用计量、私有会话隔离、来源撤权、取消和迟到结果；证据位置与重复命令见[P7–P8本地交付与验收](P7-P8本地交付与验收.md)。样本量、未覆盖型号/软件、用户反馈与实际设备验证分别报告，满意率不当总体准确率；旧项目数据不继承。

工程实验覆盖服务期限及分类/环境竞争、私有会话隔离、撤权/取消/迟到、调用未知、全部MQ/外部存储故障、XXL重复/停机、RPC TLS/Deadline/流中断、Sentinel保护人工业务、Nacos基线、ELK积压和Zipkin不可用。报告机器、负载、样本、受理/限流、终态和失败分布，不将合成并发当生产规模，不临时新增ANN/重排/多Agent。实验产物放仓库.local，不增加实验业务表。

## 11. P9 独立交付与恢复（延期到实际部署）

镜像、Compose、生产配置、备份和联合恢复暂不实施；用户明确要求在真正部署时再做。当前交付目标是本机按开发配置启动完整系统，部署时仍需重新完成固定digest、最小上传集合、生产配置和独立恢复验收。

交付ELK有界采集/偏移/PQ/保留及权限隔离、Zipkin采样/跨语言/MQ/worker关联，验证观测故障不阻断业务。双监听readiness、接收/worker、事务准备/回查、积压/DLQ、XXL和限流分别可查。模型/工具用量仍在业务库，追踪采样不承担账目或事实。

真实验收私网认证/TLS、HTTPS同源Cookie/CSRF、history、PDF/文本上传/Range、SSE、进程关闭与重启，AI故障下人工链可用。按[部署说明](../开发/部署说明.md)暂停写入和领取、等待在途收敛，联合备份四库/XXL/Broker/Nacos规则/Qdrant及原件版本，独立环境恢复并重建ES。校验支持范围、旧新数据映射、诊断事实/来源、调用未知、未完工单及预约容量；索引按原身份恢复，问答不自动付费重跑。

## 12. 每阶段交付规则

实施前重新核对真实入口、调用者、状态和用户已有工作。按完整切片迁移消费者、模型、配置、依赖及必要测试，检查隐式入口后清理替代内容；不留平行协议/执行者，也不在文档阶段生成空实现。

按[开发规范](../开发/开发规范.md)分别报告设计、实现、构建、真实联调、部署及恢复。跳过不计通过，旧报告不能证明新工作树或新数据目标。文档合同检查与真实MySQL/MQ/模型/设备验证分别交付，自动化测试只连接隔离可销毁资源。
