# 开发改造计划

本计划安排目标系统的实现顺序和阶段完成条件。业务参考[系统设计](../设计/系统设计.md)，模块和职责按[项目结构](../设计/项目结构.md)，数据和协议按[数据库设计](../设计/数据库设计.md)与[接口约定](../设计/接口约定.md)执行。本文全部阶段共同交付同一个最终版本，不是MVP、功能分期或后续扩展路线。实施时按阶段核对对应代码并重构，阶段不得省略已确定的失败、权限和恢复合同。

当前骨架入口、已实现基础能力及验证见[根README](../../README.md#5-当前骨架与本地检查)。骨架构建通过不等于P0关键外部风险已验证，也不标记业务阶段完成。

## 1. 总体顺序

先建立必要工程合同和身份，再完成可独立使用的人工售后，随后接预约、知识和 AI，最后量化评估并交付。每阶段纵向完成页面、接口、权限、状态、迁移、失败反馈与验证，不先生成整库 CRUD，不把前端或行为检查全部推到最后。

| 阶段 | 业务结果 | 关键入口 | 完成证据 |
| --- | --- | --- | --- |
| P0 | 工程目标和基础合同可执行 | common/api、应用入口、检查与配置 | 依赖方向、纯库边界、Result/分页、双语言协议生成及关键外部风险有证据 |
| P1 | 管理员开通组织和账号，用户可安全登录 | 登录改密、组织、账号、角色与范围 | 会话、CSRF、内部核验、撤权和最后管理员并发保护 |
| P2 | 客户选择设备手动报修 | 型号/设备维护、我的设备、建单、回执与详情 | 当前归属、服务资格、幂等、冲突及未知结果 |
| P3 | 人工处理与客户确认闭环 | 客服队列、技术工作台、时间线、通知、概况 | 双人接单、转派、备注隔离、期限竞争及补扫 |
| P4 | 客户预约有限上门名额 | 时段发布、工单内申请/查询/取消、履约 | 本地事务确认、无超卖、重复取消回补及未知响应 |
| P5 | 管理员将真实资料处理并授权发布 | 系列、上传回执、修订、任务、片段核对与发布 | OSS版本、MQ持久受理、MinerU、完整切片、双索引和换版撤权 |

## 2. P0 工程合同与关键风险

根 Maven 统一工具链、BOM与插件，common/api 为普通 JAR，四个 Java 应用分别启动，Python Web/receiver/worker和前端分别管理。先定义被真实入口使用的common/base响应、分页/动作表单、BaseEnum与错误接口，配合公共BusinessException、Identifier/IdentifierConst、DecimalStringSerializer、SchemaEnum及无Spring环境快照，以及api的身份/型号/来源内部合同，不建空业务层。按项目结构逐项核对真实消费者；应用JSON、环境、异常映射和swagger装配分别归属，Entity与业务枚举仍归所有者服务。

统一Java手写普通类与注释、Controller分端、Service职责、注解SQL、分页1/10、32位标识和公开长整数字符串。api维护Java内部Feign合同及跨语言.proto唯一源；从同源生成Java message/stub与Python desk_contracts包，生成物不提交、不套手写模型规范。CI/镜像在构建时生成并打包，运行不依赖兄弟源码、不调用编译器，依赖集合按版本约定保留SDK必要传递项。网关WebFlux不接收MVC/数据库传递栈，api不反向依赖业务应用，Python不访问兄弟服务库。

建立Java、Python及前端必要检查，配置按dev/prod基础环境校验，dev连接test、自动测试显式使用隔离ci资源，本机真实配置和模板不进资源与镜像。Java/Python/Gateway/前端一次迁移Result成功0、系统1及全局分域错误，旧200业务码不兼容成功；验证编号唯一、范围、未知异常安全回退、框架状态/必要头保留及服务认证故障不误判会话失效。错误码主登记见接口约定，持久任务诊断、预约结果和状态不随响应码重写。

完成符合语义的Form继承、枚举线值、null与字段级精度合同；Java MVC接入本地OpenAPI3.0与枚举文档，Python使用FastAPI实际Schema版本，Gateway保持Reactive边界。初始测试验证入口、响应与协议边界，生成物只核对生成/打包/线兼容，不套手写模型和注释规则。入口健康与业务验收分别核对。

对高风险依赖先做隔离小样本：MySQL生成列唯一/JSON/UTC/锁等待取时、MinerU CPU中文文字与扫描件、百炼1024维向量及Qdrant过滤/快照。验证knowledge事务消息半消息→本地COMMITTED→Broker确认/回查→Python SimpleConsumer落MySQL再ACK→worker，覆盖半消息未知、DB提交后二次确认丢失、生产者重启、准备到期与暂停后迟到提交、ACK丢失、取消先到及跨语言JSON信封。协议风险验证Java/Python双向TLS RPC、服务凭据、状态详情、optional/时间、Deadline/取消、原件流中断及摘要，核对RocketMQ与业务gRPC/Protobuf依赖收敛。隔离验证Redisson锁/watchdog、Sentinel网关Reactive及RPC生命周期/Nacos规则、XXL注册/触发/回调和跨语言Zipkin链路，小样本与证据放系统临时目录。风险不阻断人工链，但不能用模拟结果完成知识排障验收。

## 3. P1 身份、范围与治理

建立 user 库的组织、账号、角色关联、客户范围和审计，安装所属会话表及迁移历史。显式初始化唯一服务商和首名管理员，不设默认口令，重复初始化不覆盖密码，所有最后管理员保护走共同事务边界。

页面同步完成登录、首次改密、重置、退出、组织、账号、角色和客户范围。区分身份未确认、未登录、已登录和探测失败；会话轮换、密码及角色变化失效，强制改密只开放必要入口。DESK_SESSION与X-CSRF-TOKEN遵守接口约定；验证文档调试仍需真实身份和CSRF、dev仅私网开放、prod默认关闭，业务HTTP状态与code保持一致。

在 desk-api 定义 user 内部合同，业务服务核验当前身份后再授权资源。验证伪造身份头、停用组织/账号、撤权、跨客户、调动后的历史、CSRF和管理只读POST。客户角色固定 CUSTOMER_USER，角色不是租户全权授权。

Java接入Nacos注册配置、Feign与LoadBalancer，跨语言接入gRPC/Protobuf、私网TLS及逐调用方凭据；user的HTTP/RPC入口复用同一身份Service。明确路由、连接/总预算、错误详情和内部授权，验证RPC依赖失败不误报用户登录失效。user接入Redis有TTL的登录失败防刷，当前身份与Session仍归MySQL。统一Java/Python JSON日志与W3C追踪，接入Gateway Sentinel及Java身份依赖保护，验证Nacos规则恢复、429/503及无伪成功。ELK/Zipkin此阶段验证身份跨服务样例，最终全链验收归P9。

## 4. P2 设备与报修

按实际用例建立型号、设备、工单和创建记录。管理员/客服按权维护型号、客户资产、服务期限、区域和地点；客户选本组织有效设备手动报修。设备与型号、客户固定关系及幂等范围由数据库兜底。

交付设备维护、我的设备、报修表单、工单列表/详情与原键查询。未知结果保留原输入和键，服务先查回执再判断新建资格。设备到期/退役停止新业务，历史和已有工单履约分别授权。

验证跨客户、设备不匹配、截止日、同键重放、同键异义和提交响应未知。MySQL迁移、复合FK、标识、JSON和时区真实验收，失败DDL不能靠删库或默认baseline修复。

## 5. P3 人工处理闭环

完成客服分派/转派、技术人员接单、请求补充、客户补充、评论、优先级、解决、客户确认/未解决、取消。工单状态、事件和相关通知同事务，人工动作版本与回执一致。处理人撤权后由范围内客服转派，不能让旧处理人继续操作。

页面交付客服队列、技术人员待办、工单时间线、通知和对应概况。公开内容与内部备注隔离，概况用独立普通 Service/Mapper，不新增报表实体。

实现XXL-JOB Admin技术库及ticket预定义BEAN有界期限处理器，自然时长计算响应和确认期限，重复触发、停机恢复后有界补扫。验证双人接单、动作重投、首次响应超期与接单竞争、客户退回与自动关闭竞争、通知唯一和读取撤权。

完成“客户报修 → 客服分派/技术处理 → 客户确认”的真实浏览器闭环，服务错误不能显示空队列或伪成功。

## 6. P4 上门预约

容量来自人工核对的区域出勤安排。实现MySQL固定锁序、资格、有效预约唯一、条件扣减、取消回补和履约；预约结果、容量、事件与通知同一短事务提交，201返回CONFIRMED/REJECTED，幂等重放返回原结果。该业务不接MQ、Redis库存或申请过期扫描。

页面包括时段草稿/发布/关停、工单上门资格、客户申请/查询/取消和技术人员登记真实结果。网络超时保留原键查询，不显示未持久的已确认状态，不持续轮询虚构待确认阶段。

用真实MySQL验证锁等待后取时、工单资格变化、约满、关停、重复提交、并发取消/履约、重复回补和未知响应。合成多个有权工单竞争少量名额，核对reserved_count与CONFIRMED/FINISHED数量、事件及通知；实验验证容量不变量，不把预约包装为秒杀，也不据此声称生产吞吐。

## 7. P5 知识处理与发布

建立资料系列、修订、型号关联、事件、kb_index_job业务尝试/事务事实和AI任务/片段。knowledge管理OSS原件、发布及指令提交，AI管理解析、索引及远端收敛，各自库和合同独立。

交付PDF上传/回执、精确版本原件、修订页面、RocketMQ事务生产及TransactionChecker、XXL knowledgeIndexPrepareExpire，AI receiver短事务受理后ACK、worker独立执行。SUBMIT/CANCEL准备与提交、AI受理及执行状态分别展示；不设outbox或发送扫描器。验证完整信封、半消息未知、准备到期与迟到请求互斥、MySQL提交后二次确认丢失、DB不可达返回UNKNOWN、生产者重启回查、ACK丢失、取消乱序、回查耗尽、DLQ及消息过期。管理员核对后replay-command只重放原已提交指令，取消优先，不换jobId；已发布任务/片段固定，资料内容或模型空间变化使用新修订。

真实中文手册验证结构、物理页、表格和错误码，完整切片清单一次固定，稳定ID写ES与Qdrant，两路可检索才成功。恢复按原阶段补副本，不重复解析，不假设未持久向量无需再次付费。

页面交付任务阶段、取消/核对、片段核对、发布/替换/停用恢复。通过gRPC GetStatus核对摘要/lastCommand/解析收敛，通过ReadOriginal server-stream读取固定原件并校验完整性。验证决策事务持锁期间暂停进程、服务端空闲断连回滚及恢复后禁止旧提交，并核对池失效连接重建。验证Redisson同请求上传互斥、抢锁超时、watchdog/锁丢失、Redis不可用、同键异义、唯一回执、OSS未知与孤立对象、索引部分失败、过期worker、撤权及原件保护。回收需运维窗口确认无引用/在途任务，不预建自动删原件任务。

## 8. P6 授权排障与草稿

先固定题集和检索基线，再接生成。题集覆盖故障码、口语、缺关键条件、错误型号、旧修订、无证据、撤权和扫描页。

实现knowledge授权前置、ES/Qdrant双路、MySQL回查、RRF、证据预算、Prompt和真实引用。任一路失败与证据不足分别表达，来源按实际上下文固定，历史复核全部来源。百炼只提供模型API，不托管项目RAG。

页面交付本人设备会话、受理、阶段流、引用原件、历史、取消和原键查询。终态和正文/引用原子保存后交付，断流重查，不自动重发问题。worker按执行令牌续约，过期问答中断，不自动付费重跑。

草稿固定截止运行，模板预填本人输入和用户确认操作，不额外调用模型、不扣生成次数；助手建议不能写成已执行事实。用户编辑确认后ticket复用建单用例，核对本人/组织/设备/期限/来源和sourceDraftId唯一性；原工单重放不再次消耗草稿。AI故障保留输入并支持不带来源的手动报修。

验证会话活动唯一、排队预算、限额、模型超时、取消/完成、身份变更、来源撤权、过期执行权和迟到结果。模型建议不作为已执行事实，模型不运行客户设备命令。

## 9. P7 工作台与管理整合

整合已交付页面和角色导航，补齐有权反馈、共享撤销、检索诊断、事务/消费异常核对与概况。P7不承担此前所有页面的首次实现，不复制一套管理员业务服务。

反馈默认只归本人，知识管理员需共享许可及全部来源权限才能展开，处理与撤销共享通过版本竞争。诊断和排障共用检索规则，概况不授予底层正文权限。组合角色、跨客户、组织调动和通知/历史缓存清理通过浏览器验证。

## 10. P8 评估与故障实验

固定语料、题集、模型、空间、Prompt、候选数和预算，分别比较关键词、向量、混合的召回、关键事实、引用/页码正确性、拒答/澄清、延迟及费用。满意率只代表已评价样本，不能当总体正确率，未知Token不填0。

并发和故障报告注明机器、配置、并发、窗口、样本及生成方法，统计受理、限流、预约确定结果、异步终态和恢复。覆盖ES/Qdrant失效、部分写入、半消息未知、本地提交后二次确认丢失、事务回查/DB故障/耗尽、暂停请求晚于准备终止后恢复、消费受理后ACK丢失、取消乱序、DLQ/受控重放、保留期外恢复、XXL重复/停机、上传锁丢失和对象未知。验证RPC TLS/服务凭据故障、Deadline及原件流中断，Sentinel保护下人工业务隔离、Nacos规则失联/冷启动基线、ELK积压/磁盘及Zipkin不可用，不将合成并发或微服务数量当成生产规模。

固定使用精确向量召回、关键词/RRF与已定义候选预算，评估报告说明覆盖和局限，不在交付时新增ANN、重排或另一套流程。评估入口按职责放CI/实验目录，结果放仓库外，不增实验业务表。

## 11. P9 交付与恢复

构建应用、ES/SmartCN与MinerU派生镜像，记录digest、平台及模型空间，完成可独立上传的Compose/空模板/启停集合。检查产物不含本机真实配置/模板、凭据或兄弟源码依赖，生产OpenAPI/Swagger默认关闭且不经Gateway公开。服务器无需源码和构建工具，启停不删数据，已有环境不自动接管。

交付Logstash只读采集/持久sincedb/PQ、独立ES日志模板/生命周期、Kibana看板及Zipkin有界内存存储。用真实Java内部HTTP、跨语言gRPC、MQ生产/回查/接收、worker和问答验证traceId/spanId/jobId关联与采样，覆盖采集/追踪失败不阻断业务、重启历史保留边界及日志/知识ES权限隔离。任务页面、API双监听readiness、receiver/worker、事务准备/回查异常、积压/DLQ、XXL执行及限流事实分别可查。

真实验证内部认证、RPC私网端口/TLS/证书轮换、HTTPS同源Cookie/CSRF、history、上传/Range、SSE、API双监听与任务进程关闭重启、日志脱敏及磁盘限制。验证AI故障下人工闭环可用，健康、业务、联调、部署分别提供证据。

暂停相关写入和任务领取、等待在途操作收敛，联合备份四业务库及XXL技术库、Broker、Nacos/Sentinel规则、Qdrant、被引用OSS版本及恢复配置，独立环境恢复并重建ES知识索引。先核对索引业务提交/取消事实及AI墓碑再恢复回查/接收；核验原件摘要、发布授权、历史、未完工单及预约容量。索引沿原身份核对恢复，问答不自动付费重跑，完整步骤遵循部署说明。

## 12. 每阶段交付规则

实施开始时再核对该阶段真实入口、调用方、状态与差异，在负责边界重构。改造同步迁移消费者、模型、配置、依赖和测试并删除被替代内容，不留下平行流程。

验证按[开发规范](../开发/开发规范.md)执行。替身、进程健康、构建、真实依赖、部署及恢复分开报告，跳过不计通过；自动化测试不连接共享业务库，数据库、事务MQ、HTTP/RPC及查询/索引正确性用隔离真实组件验收。每阶段交付可审查的结果及实际证据，不能用设计文档代替实现完成。
