# P4–P6实施与验收

本记录覆盖现场服务、PDF/Markdown知识和双侧私有排障的代码、配置、制品及隔离业务验收。业务合同仍以[系统设计](../设计/系统设计.md)、[接口约定](../设计/接口约定.md)和[数据库设计](../设计/数据库设计.md)为准。实施基于现有工作树，不包含提交、推送、生产部署或共享业务库迁移。

预约使用工单→预约→时段锁序，取得全部锁后另查数据库UTC时间。取消只在开始前回补一次，履约只能在开始后登记。关停时段不撤销已确认预约，页面和回执不制造PENDING业务状态。软件验收中的履约是合成登记，不能据此声称实际上门。

knowledge独占OSS凭据；AI经双向TLS原件流读取，核对长度、SHA及RPC最终状态，流取消和背压均有明确资源释放。Java↔Java继续使用Feign/HTTP，Java↔Python使用desk-api唯一.proto源；索引只经RocketMQ原生事务，没有HTTP提交旁路、outbox或自动发送扫描器。

上传、索引、生成及人工动作在当前授权内先核对原键。草稿采用事实唯一归ticket，AI不维护第二份consumed状态。旧生成依赖的来源失效时，正文、引用、摘录、来源事实及草稿一并隐藏；恢复资料不会替旧运行重新生成内容。

## 2. 验证环境与已取得的业务证据

2026-11-14使用本任务独占回环MySQL 8.4.13、Redis、RocketMQ 5.5.0 Broker/Proxy、ES 9.5.6 + SmartCN、Qdrant 1.20.0、XXL-JOB 3.3.0和Zipkin 3.6.1。Java四个应用、AI API/receiver/worker使用临时CA及独立服务令牌；真实OSS私有版本存储、MinerU和百炼仅处理公开合成规程及合成反馈。未写共享业务库，未将测试账号、密钥或证书纳入Git/制品。

| 用例 | 验证结果与边界 |
| --- | --- |
| 现场服务 | 真实MySQL容量竞争、同键回执/异义、取消一次回补、履约及冲突、时段草稿修改/冻结、权限、事件/通知通过 |
| Markdown发布 | 实际OSS精确版本→原生SUBMIT→receiver落库→worker→真实Embedding→ES/Qdrant复核→发布；原SUBMIT受控重放不重复片段 |
| MQ恢复与DLQ | 独立Topic/组、真实生产TransactionChecker读取MySQL事实：半消息UNKNOWN→本地COMMITTED→关闭重建生产者→回查恢复；受理提交后故意丢ACK，重投仍唯一；准备过期ABORTED/ROLLBACK；取消先到晚SUBMIT不复活；有效但异义摘要拒绝ACK，专用组retryMaxTimes=2后以Broker DLQ偏移确认入队。消费测试使用原生SDK及生产IndexService，不运行付费worker，不等同于生产16次阈值或回查耗尽验收 |

| 私有排障 | 实际客户RAG及真实引用、原键、逐次用量、SSE终态；技术私有助手及工单只读工具；跨拥有者读取拒绝 |
| 人工草稿 | 客户确认事实→模板→mTLS ValidateDraft→人工建单；技术已有建议→编辑→正式记录；并发采用同草稿只有一个成功，过期拒绝新动作，已成功动作原键仍返回回执 |

| 事实及反馈 | 更正追加保留前驱，旧事实active=false；客户反馈默认私有、显式共享及版本化撤销；技术无帮助为RECORDED且拒绝共享 |
| 浏览器纵向验收 | 仅操作Chrome项目标签页：时段建立/编辑容量/发布；新系列→Markdown文本编辑上传→实际索引成功→核验发布；客户新私有会话→零模型澄清→确认反馈→模板草稿→人工编辑→正式工单及时间线。真实技术助手、并发和恢复另由HTTP/RPC验收，不把其计为浏览器操作 |
| 反馈分支与风险 | 实际模型依据已完成检查的用户反馈给出下一步；明确电气风险由规则停止并转人工；错误版本不套用旧资料且零模型调用。风险是用户报告，不是设备观测 |
| 调用失败计量 | 真实MySQL和生产用例验证非法响应保留已确认用量、取消后旧令牌不可改账；供应商响应是明确夹具，未冒充付费真实调用 |
| Nacos/Sentinel | 在独立命名空间向实际Gateway下发规则；并发请求出现预期401/429，非法配置保留最后有效规则、空规则回到打包基线；受控SSE协议夹具验证订阅期间占用并在取消后释放，夹具不算真实诊断 |
| XXL-JOB | 实际执行器注册、Admin触发、回调200、PREPARING→ABORTED及重复触发幂等通过；无周期示例任务启用 |
| Zipkin | 按持久trace_context核对真实同traceId和父子span：Java→MQ→receiver→索引worker、Web→问答worker；仅服务名可见不作为接续证明 |

曾出现原件RPC暂不可用、MinerU上传响应未知及模型字段类型错误，均保留原失败事实。只读原件在一个总期限内有界重试；已知解析身份继续查询原任务，不重新创建；模型使用严格JSON Schema并继续本地校验。未将失败任务改写成成功，也未把取消当作远端解析已停止。

## 4. 明确的交付限制

用户已确认当前没有办公打印机和Microsoft 365测试环境，设备/固件、真实租户授权及相应故障恢复保留为未验证。合成样例、用户报告与实际设备观测分别标明，不能宣称真实客户问题已经解决。

P7工作台整合与知识管理员反馈处置、P8对照评估和质量/成本统计、P9镜像交付、联合备份及隔离恢复不在本次P4–P6范围。生产HTTPS、生产独立凭据/网络、非空旧库数据映射和生产迁移尚未实施。P0全量故障矩阵中的Broker回查耗尽、生产重试阈值下的完整故障矩阵及完整ELK采集/故障恢复仍按未验证登记；现有原生事务、持久受理、取消/重放和Zipkin分项证据不能冒充全矩阵通过。
