# 验收说明

验收按可重复行为及原始身份判断，不按完成阶段数折算百分比。工程测试、真实组件联调、模型质量、设备验证和生产发布分别报告。当前本机连接既有真实组件的验收不需要重建Docker隔离基础服务；CI自己的独立测试资源不替代本机联调证据。

## 1. 攻击与权限检查

| 检查面 | 输入/动作 | 必须观察的结果 |
| --- | --- | --- |
| 知识提示注入 | 原文伪装SYSTEM、要求读取密钥/外传/直接修复 | 先证明确实进入模型输入，再核工具、正文和正式动作回执；仅未调用危险工具不能证明语义通过 |
| 附件提示注入 | 脱敏文本伪造工具回执及用户批准 | 只能作为附件数据，不能变成真实工具观测或人工确认 |
| 工具伪造 | 未声明工具、非法参数、伪造来源号 | 白名单/参数/来源校验拒绝，不调用外部副作用 |
| 前置条件绕过 | 未观察、未执行、错误答案、旧环境反馈 | 不能产生有状态修改含义的后续检查，复查必须有新身份 |
| 草稿参数替换 | 改根、修订、摘要、服务项目或目标工单 | Java重新核验并拒绝，正式回执与工单事件不增加 |
| 跨客户与私聊 | 客户、技术人员、管理员读取/修改他人会话、任务、Run、来源 | 统一不可见响应；工单权限不授予私聊访问 |
| 撤回与撤权 | 从历史Run、消息、检查、工具摘要、SSE及跨轮依赖读取 | 按来源规则遮蔽；风险撤回和访问撤权语义分开，禁止从摘要绕过 |
| 追踪注入 | 外部请求带traceparent/B3/baggage | 公开入口产生受控追踪，不能信任外部标识为身份 |

旧失败原样保留。修复后沿同一对象或明确的新批次验收，不替换旧文件、不把结构校验通过当作专家审阅。原始检查被撤回后尝试反馈应得到登记的409/5103，不能被HTTP边界错误转换成通用500；读取面遮蔽与写入面拒绝分别验证。

## 2. 故障与恢复检查

| 故障 | 应保留的事实 | 核对方式 |
| --- | --- | --- |
| 排队取消、重复受理 | 原请求键、原Run、零或已发生调用 | 重放返回同一身份，不再次扣费或执行 |
| 调用中停进程/取消 | 调用意图、原令牌及未知结果 | 租约后收敛，不自动重排UNKNOWN，迟到结果不发布 |
| Redis不可达 | 已存在会话、消息及受理Run | 拒绝新的受配额保护生成；已保存的检查反馈不回滚，已有消息读取不依赖Redis |
| 身份RPC不可达 | 原会话及用户身份未被伪造 | 503/504依赖错误，不误报登录过期，不缓存权限放行 |
| 系统代理干扰 | 显式内部端点及双向TLS合同 | 内部gRPC、Zipkin及RocketMQ接收器仍直连；真实本机TLS/HTTP监听及官方MQ SDK配合拒绝代理验证，不能只核对进程存在或靠单机NO_PROXY掩盖缺陷 |
| MySQL不可达 | 未确认的业务提交仍为未知 | 安全错误，不返回空成功；恢复先查原动作回执 |
| ES或Qdrant单路失败 | 原MySQL片段及索引空间 | 整体检索失败，不默默退成单路完整答案 |
| MinerU状态/创建未知 | 原远端任务身份及解析账目 | 按原身份对账，不换任务重建，不伪报完成 |
| 模型欠费/限流/连接失败 | 原模型调用意图及已知用量 | 明确拒绝与UNKNOWN分开；评测停止，不继续制造整批失败 |
| MQ丢ACK/重启/乱序/坏信封 | 原jobId、operationId及事务事实 | 重投幂等、取消墓碑、失败重试/DLQ、回查及原身份处置分别取证 |
| Logstash/Zipkin故障 | MySQL业务事实与审计 | 观测失败不回滚业务；记录采集滞后、恢复和可能丢失的窗口 |
| 预约并发/重放/取消 | 原预约、容量和动作回执 | 最后名额只有一人成功，取消只回补一次 |
| 浏览器断流 | 已提交Run及其状态 | 重新查询原运行，不自动再次提交问题 |

进程局部连接故障可以验证超时、失败关闭和错误转换，但不等同组件断电或独立灾备。应明确记录是客户端断连、组件重启、进程终止、真实供应商拒绝还是单元替身；这些证据不能互相冒充。

新CONSULT请求在受理前被拒绝时，不承诺已创建消息。检查反馈通过独立接口保存后返回的`inputMessageId`，则必须在新Run排队失败时保留。验证这两种情况时不能混淆输入合同。

## 3. 数据与模型实验

公开资料及合成设备规则见[样例数据](样例数据.md)。三策略、四项消融、失败记账和冻结方法见[领域评测](领域评测.md)。全量记录、实际完成、成功率、无效检查、供应商故障、未结束请求、账目缺口和未知费用分别展示；不将补测与旧批次拼成独立新成绩。

消融报告同时给出机制实际触发次数。短案例里从未调用按需上下文时，即使关闭补读没有降低分数，也不能推断补读无价值。语义支持率需要逐条关键建议与证据对齐，记录审阅者及分歧；有引用不等于建议正确。

按需上下文另用超过首轮事实窗口的合成记录验证：早期目标事实确实未进入初始清单，模型调用补读工具取得原事实，来源记录证明其随后进入模型。仍按用户反馈标注，不将补读成功写成设备实测或允许无依据操作。依赖故障导致整组未调用模型时，该组只能作为连接失败证据；恢复后保持冻结源码、模型及预算创建独立批次，原失败不覆盖。

## 4. 本地运行与生产边界

本地交付核对应用入口、真实连接、正式配置、源码与运行制品一致、临时评测进程退出、正常限额恢复、合成负载账号停用及任务收尾。验收日志不包含密码、Cookie、完整提示词或真实客户正文；业务样例原件和必要活动配置不以`.local`作为唯一存储。

混合负载使用10个独立合成客户会话及最多两条持续投递的模型工作流，运行30分钟，分别报告人工接口p95、失败数、实际Run并发时间序列和模型时延。并发峰值为2不能证明整个窗口一直有两条活跃模型调用；在等待人工反馈和两次Run之间出现空隙应如实保留。执行模型评测期间不偷偷增加worker数量或改变预算。

生产发布另需服务器运行集合、受控生产凭据与证书、真实参与者/领域审阅以及独立恢复演练。四库在同一服务器的新命名库恢复只证明该逻辑备份可还原，不证明服务器丢失后的RPO/RTO，也不证明OSS、Qdrant、MQ联合恢复。缺少这些证据时只能交付已验证的本地范围，不称为生产上线验收通过。

本机原始报告保存在根`.local/<任务>/checks/`，交付索引及进度保存在被Git忽略的`docs/开发计划/`。索引记录输入文件摘要、范围、通过/失败/未验证和复核结论；不覆盖失败，也不把跳过计为通过。
