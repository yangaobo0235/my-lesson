# 部署说明

本文定义最终系统的开发连接、镜像交付、运行配置、启停、故障处理及备份恢复。模块与文件见[项目结构](../设计/项目结构.md)，版本见[版本约定](版本约定.md)，业务及持久事实见[系统设计](../设计/系统设计.md)和[数据库设计](../设计/数据库设计.md)。端口与预算是项目初值，必须真实联调，不能据文档宣称已经上线。

## 1. 部署范围

开发时Windows运行Java、AI三个进程及Vue，openEuler Docker提供基础服务，通过受控私网或SSH转发连接。交付时同一服务器运行预构建应用及基础镜像，浏览器只访问HTTPS统一入口。最终范围包含MQ、XXL-JOB、Redisson、Sentinel、ELK及Zipkin，不以开发阶段延后接入为由省略验收。

| 单元 | 确定部署方式与数据 |
| --- | --- |
| gateway、user、ticket、knowledge | 各一个Java容器；common/api不运行；ticket/knowledge嵌入XXL执行器 |
| ai-api、ai-receiver、ai-worker | 同一AI镜像的三个进程，分别HTTP+gRPC、MQ短事务受理、持久任务执行，共用AI业务所有权 |
| web | Vue静态产物与Nginx，同源代理Gateway |
| MySQL | 四个服务库/账号、Session技术表，另有独立xxl_job_{env}技术库/账号 |
| Redis | user登录防刷、AI日次数、knowledge Redisson锁；ACL按用途隔离 |
| Nacos | 单机发现、配置、Sentinel规则，Derby持久化，认证开启 |
| RocketMQ | 单NameServer、单Broker及gRPC Proxy，持久消息与消费元数据 |
| XXL-JOB Admin | 同版技术SQL、调度配置/记录、认证及执行器accessToken |
| ES、Qdrant | ES隔离知识与日志；Qdrant持久向量及snapshot |
| Logstash、Kibana | 只读采集应用JSON、持久偏移/PQ、运维日志查询 |
| Zipkin | 单实例有界内存存储，仅保存近期采样span，重启可丢失 |
| MinerU | 独立CPU解析镜像、固定权重、任务与结果目录 |
| OSS、百炼 | 出站HTTPS，原件及模型分别授权 |

这是单机部署，不承诺高可用。重复触发、请求重试、重启或部署重叠仍按多执行者可能性设计正确性。已有手动容器和数据卷不自动接管或删除。Sentinel以应用SDK与Nacos规则工作，不依赖另部署控制台；Redisson是knowledge客户端，不是新增服务器。

开发机与组件服务器均须启用系统时间同步，并核对UTC时间与MySQL `UTC_TIMESTAMP(6)`；时区展示不同不代表时钟不同。Run总Deadline跨数据库与worker使用，明显时钟偏差会导致新任务立即超时，不能靠放宽预算或修改业务记录绕过。Windows通过日期和时间设置或管理员执行`w32tm /resync /rediscover`同步，openEuler通过`timedatectl`、`chronyc tracking`检查；休眠或虚拟机恢复后再次核对，再启动付费评测。

## 2. 文件与镜像交付

| 文件范围 | 职责 |
| --- | --- |
| .github/docker/Dockerfile.java | Java统一构建/运行定义，通过DESK_MODULE选择四个应用之一 |
| .github/docker/Dockerfile.ai | uv锁定环境，从唯一.proto生成并打入wheel，同镜像启动API/receiver/worker |
| .github/scripts/ | 协议生成/兼容检查与制品编排，不放应用/服务器启停、运行说明或真实配置 |
| .github/docker/Dockerfile.web、nginx.conf | Node构建，Nginx提供静态/history/API/SSE |
| .github/docker/Dockerfile.elasticsearch、Dockerfile.mineru | 同版SmartCN及固定CPU解析权重的派生镜像 |
| deploy/compose.yml | 唯一运行定义，引用预构建镜像，不含源码build |
| deploy/.env.example、start-server.sh、stop-server.sh | 空凭据模板及从自身目录读取同一运行定义的启停 |
| deploy/rocketmq/ | NameServer/Broker/Proxy直接使用的认证、地址、Topic/消费组初始化配置 |
| deploy/xxl-job/ | 同版官方技术SQL及确定的BEAN调度初始化数据 |
| deploy/logging/ | Logstash pipeline/settings、ES日志模板/保留、Kibana看板及运行初始化文件 |
| deploy/nacos/ | 实际初始化所需的非敏感服务配置与Sentinel规则 |

服务器只接收deploy最小集合及镜像，不需要源码、JDK、Maven或Node；配置集合脱离仓库独立运行，不引用../或本机路径。应用配置与日志装配归各模块，Dockerfile及镜像内Nginx配置归.github/docker，说明归docs。只按实际运行挂载创建文件，不复制参考工程全套模板。

应用镜像从仓库根构建，Java共用同一个包含verify的构建层，分别传入desk-gateway、desk-user、desk-ticket、desk-knowledge作为DESK_MODULE。AI构建先按锁文件生成协议并检查wheel，再安装无开发工具的锁定依赖和wheel；运行层不包含源码、测试、uv或Maven。构建上下文采用.dockerignore白名单，并再次排除本机配置、密钥及旧协议生成物。以下命令只生成本机镜像，不启动或接管现有服务：

```shell
docker build -f .github/docker/Dockerfile.java --build-arg DESK_MODULE=desk-gateway -t service-desk/gateway:local .
docker build -f .github/docker/Dockerfile.ai -t service-desk/ai:local .
docker build -f .github/docker/Dockerfile.web -t service-desk/web:local .
```

Java/AI镜像以UID/GID 10001运行，日志挂载目录需预先授予该身份写入权限；Java各应用使用独立子目录，AI三个进程分别挂载独立日志目录。RocketMQ Python SDK在导入时使用原生/home/desk/logs/rocketmq_python目录，receiver启用只读根文件系统时须为/home/desk/logs提供可写的有界tmpfs或受限日志卷，不通过重定义HOME改变路径。Java使用JRE，AI三个入口分别为默认CMD servicedesk_ai、servicedesk_ai.receiver及servicedesk_ai.worker；部署覆盖command时只填写模块名。镜像默认prod，仍须完整提供独立账号、证书和业务配置，缺配置启动失败。

Web以nginx非特权用户监听8080/8443，交付映射80/443，实际证书只读挂载到/run/secrets/web-tls.crt及web-tls.key并授予容器用户读取权限，禁止把证书编入镜像。8080除进程探测/health外跳转HTTPS；8443提供history、静态文件及同源/api/代理，gateway为Compose服务名。代理覆盖外部转发头、关闭自动上游重试、缓存及响应缓冲，SSE读超时360秒；访问日志不记录资源路径、查询参数或正文。/health仅证明Nginx运行，不能代表Gateway或业务就绪。

真实.env在服务器创建并限权，更新不覆盖。构建上下文排除application-local真实文件、密钥、缓存和生成物；空application-local.example.yml仅作为构建阶段配置合同测试输入。Java资源复制及JAR同时排除本机真实文件和空模板，运行层只接收JAR。本机镜像归档、备份及一次性验收证据放仓库 .local/<任务>/<用途>/，由 Git 忽略并排除构建上下文；服务器活动配置、凭据、偏移和队列保留在服务器的持久目录。

跨语言.proto仅由desk-api维护；Java构建生成至target并编入api JAR，Python镜像构建在同一仓库上下文从该源生成desk_contracts并装入wheel，再复制锁定运行环境。运行不依赖兄弟源码，服务启动不生成协议；不额外安装独立protoc，Python环境按RocketMQ SDK声明保留固定grpcio-tools，不通过删除传递依赖裁剪。RPC CA、服务端证书/私钥和每调用方凭据使用服务器受限只读secret挂载，配置仅引用容器内路径；不提交真实证书/密钥，不把私钥放Nacos或镜像。证书SAN覆盖实际私网服务名，开发CA独立，校验失败拒绝调用。

ticket诊断附件使用独立的`DESK_TICKET_OSS_REGION`、`DESK_TICKET_OSS_ENDPOINT`、`DESK_TICKET_OSS_BUCKET`、`DESK_TICKET_OSS_ACCESS_KEY_ID`、`DESK_TICKET_OSS_ACCESS_KEY_SECRET`，绑定`desk.attachment-storage`。前缀固定`ticket/{test|ci|prod}/attachments/`，与resource-env一致；桶需开启版本管理，凭据只允许本前缀的创建、精确版本读取及元信息核验，不授予删除或知识前缀权限。缺配置阻止ticket业务启动；AI不持该凭据。上传未知只读对账，维护重传须先确认外部旧调用已收敛且对象确定不存在，不以一次404推断未发生。

宿主只映射真实消费者需要的端口；Logstash读文件，不映射无消费者的5000/5044输入；Qdrant6334、ES9300不对外发布。Nacos8080、Proxy8080和Admin8080是不同容器端口，宿主不得冲突。中间件/控制台/内部HTTP绑定回环或明确私网，身份认证不能替代网络隔离。

容器按服务名及容器端口访问，不用自身localhost访问其他容器。当前组件服务器为192.168.23.66，开发机地址另由DESK_APP_HOST填写；Broker/Proxy公布地址、Nacos注册和XXL执行器注册地址须对实际消费者可达，不能照抄容器内网地址。/internal/v1和gRPC不经Gateway通配路由。Feign继续Nacos发现；跨语言RPC显式配置目标私网服务名/DNS及TLS名称，不增加Python Nacos消费者或自研resolver。生产关闭RPC reflection，grpc.health.v1仅私网受控探测，不暴露业务数据。

## 4. 基础服务准备

先核对uname -m、Engine/Compose v2、端口、磁盘、内存及云网络。按版本约定构建/拉取并记录digest、平台、制品及模型空间。ES构建同版analysis-smartcn；MinerU固定Python3.12、Basic/CPU/ONNX、原生库、权重及V1任务协议，不在启动时下载权重。不以镜像可拉取或健康代替业务验收。

Java构建使用maven:3.9.9-eclipse-temurin-21，运行eclipse-temurin:21-jre；AI使用python:3.12.16-slim-bookworm及锁定uv；Web由node:24.22.2-bookworm-slim构建、Nginx运行。维护标签需记录digest并验证目标架构。

MySQL业务库为desk_user_{env}、desk_ticket_{env}、desk_knowledge_{env}、desk_ai_{env}，业务环境test/prod，自动测试独立ci。InnoDB、utf8mb4_0900_bin、严格模式、UTC、READ COMMITTED及caching_sha2_password与数据设计一致。当前开发由root初始化并连接各自test库；生产及隔离测试运行账号只获本库必要DML，迁移账号独立DDL。三个Java服务启动执行Flyway，AI API在就绪前执行Alembic，user初始迁移同时安装MySQL方言Session表。先建空库，再启动所属应用；已有手工结构按[数据库初始化与迁移](../sql/README.md)比对后显式接管。不使用ORM隐式建表、自动baseline/stamp、clean或删卷绕过迁移失败。

XXL Admin只使用xxl_job_{env}，安装3.3.0同tag官方8表SQL，移除示例任务和默认口令，再受控导入ticketDeadlineScan、knowledgeIndexPrepareExpire两个预定义BEAN、执行器及accessToken。执行器无该库账号。初始路由FIRST、阻塞策略丢弃后续、过期触发只补一次、调度失败重试次数0；业务库有界扫描收敛期限，不承担MQ发送。不能开放GLUE脚本/任意SQL给普通业务管理员。

RocketMQ显式创建desk-knowledge-index-command-{env}，设置message.type=TRANSACTION及对应消费组，关闭自动创建以免环境拼写产生旁路；部署前核对Topic属性，不能沿用NORMAL类型。单Broker采用同步刷盘，持久commitlog、consumequeue及配置；无副本不宣称硬件容灾。启用Proxy与ACL，限制knowledge生产和AI对应消费权限。消息保留72小时、maxDeliveryAttempts=16（含首次）、SimpleConsumer invisibleDuration30秒；核对Broker重试/DLQ配置实际生效。接收进程在5秒受理事务后ACK，不把长解析塞入不可见期。

RocketMQ5.5.0消费组原生配置使用retryMaxTimes=15，Proxy下发的maxAttempts为retryMaxTimes+1，对应含首次的16次交付；不能把retryMaxTimes直接填16。超限消息由Proxy转死信，Broker转存又会增加ReconsumeTimes，该字段不是应用收到消息的次数。验收同时核对消费组配置、receiver实际拒绝次数、原消息身份及DLQ正文，不凭字段名推断计数。坏信封不得ACK伪成功或写入业务库，进入DLQ后保留原因并由运维核对，禁止原样无限重放。

Broker显式设置transactionTimeOut=60000毫秒、transactionCheckInterval=60000毫秒、transactionCheckMax=240，覆盖30秒本地准备及5秒短事务预算；这些是目标初值，不沿用服务端默认。检查是周期调度且受负载/存储/过期影响，不能将次数×间隔当成精确恢复时限或72小时无限回查。knowledge生产者启动必须向该Topic注册TransactionChecker并保持连接，重启重新注册；回查读取业务库，持久COMMITTED确认、ABORTED回滚、未决/依赖失败UNKNOWN，过期准备按同锁序终止后才回滚。Producer可运行及回查可用分别探测；故障窗口应早于实测回查预算结束，回查耗尽/丢弃须告警并进入受控核对重放，不能无声丢任务。Broker/Proxy、半消息、本地提交、二次确认丢失、重启回查、实际接收、落库/ACK、消费重试及DLQ分别验证。

Nacos开启认证及随机token、非空identity key/value，持久Derby；Java显式spring.config.import与namespace/group。Sentinel按环境/应用分别维护网关API分组、flow/degrade等真实消费规则，独立规则dataId；启动基线归对应应用资源，凭据不放公开配置。Redis按desk:{env}:前缀区分user/ai/knowledge用途，ACL允许Redisson所需锁Lua/订阅及有限键范围，不能只授GET/SET导致运行锁失效；不配置会淘汰活跃锁的内存策略。内存不足拒绝新保护操作并告警，不以丢锁换空间。

Qdrant启用api-key、持久storage/snapshots；collection为desk_chunks_{env}_te4_1024_v1，1024维Cosine，为index_job_id/document_id/vector_space建keyword索引，验证wait=true、过滤、精确查询及snapshot恢复。OSS按环境私有版本Bucket，knowledge知识原件与ticket附件分前缀和独立最小权限凭据，读写与物理清理权限分离，引用版本不可提前过期。百炼只提供Chat/Embedding，不建立托管知识库或工作流。

## 5. 应用配置与预算

Java分别维护application.yml、application-dev.yml、application-prod.yml及本机模板，基础环境只选dev/prod，默认dev。application.yml统一声明组件装配、客户端、预算与日志；dev必需导入所属application-local.yml，由该文件使用已加载参数链式导入Nacos，连接test资源，填写后直接运行Application。prod连接prod资源并使用进程环境或受控运行配置，不导入开发文件。自动化测试在src/test/resources维护application-test.yml，显式选择dev,test或prod,test：环境文件中的外部导入文档在test下不激活，测试配置关闭外部客户端并使用ci资源；运行制品不含这些测试配置，不提供日常离线启动模式。common/api无应用配置，common/env只是无Spring不可变快照，由各应用EnvironmentConfig及启动校验消费。AI类型化设置覆盖三个进程各自资源，环境资源隔离一致；VITE_*仅存公开同源配置。端点、凭据、SSL、预算、环境前缀及规则关键值缺失应启动失败。

三个MVC服务以本地swagger配置显式装配springdoc，dev在受控私网开放/v3/api-docs、/swagger-ui.html，文档版本为OpenAPI3.0，prod默认关闭。AI dev私网开放/openapi.json与/docs，使用FastAPI实际生成版本，/redoc不启用，prod默认关闭。Gateway不聚合文档，也不公开代理这些入口；关闭文档不关闭正常业务或私网health。文档调试沿用真实Cookie/CSRF与权限校验，不硬编码万能Token，不暴露HttpOnly会话值。

当前实现的协议生成、安装、构建与启动命令见[根README](../../README.md#5-当前实现与本地检查)。Java从仓库根工作目录构建并以dev分别启动，dev显式读取所属模块src/main/resources/application-local.yml，不复制进入JAR；前端执行npm ci及npm run dev。AI在desk-ai先锁定安装工具并生成合同，再uv sync --locked，以uv run --locked python -m servicedesk_ai启动，默认26105。receiver/worker入口分别为python -m servicedesk_ai.receiver及python -m servicedesk_ai.worker。API拥有HTTP及mTLS双监听并先完成迁移；receiver在5秒短事务持久受理后ACK，worker独立领取索引/生成并执行终态解析收敛，不在receiver跑长任务。健康不等于任务已受理或发布已可用。

API进程ASGI lifespan同时启动/停止HTTP及grpc.aio服务，两者任一启动失败整体readiness失败；不另设第四RPC进程。先生成Python合同再启动，本地及镜像使用同一生成入口。连接按进程复用，关闭有界排空；Java RPC服务随所属应用关闭，停止接新请求、完成或中止在途调用，不留后台孤立监听。

### 5.1 本机配置与连接

| Java配置文件 | 职责与规则 |
| --- | --- |
| application.yml | 公共组件配置、服务名、监听端口、日志与预算；默认dev，不保存密码 |
| application-dev.yml | 开发test资源；必需导入本机配置文件；MVC开放开发文档 |

MySQL库（当前开发使用已有root账号，生产准备最小权限运行账号）、TRANSACTION类型的desk-knowledge-index-command-test、desk-ai-index-command-test消费组、ES SmartCN与desk_chunks_test_te4_1024_v1索引、Qdrant同名1024维Cosine集合、私有版本OSS桶、XXL执行器记录和日志采集链由服务器准备，复制本机模板不会创建这些资源。当前正式迁移安装37张自有表及2张会话表，Java三库版本为V1/V7/V5、AI为0009；四个真实开发库已逐字段核对。三个Java服务默认启用Flyway，AI API默认启用Alembic；[数据库初始化与迁移](../sql/README.md)登记空库启动、手工SQL快照及已有结构接管步骤。API迁移完成后再启动receiver/worker，避免消费者读写旧结构。XXL的ticket期限及knowledge准备超时处理器须核对执行器地址、BEAN名称及独立token后配置周期任务；当前现有开发Admin中的两项业务任务已取得成功回执，示例任务保持停用。执行器通信timeout-seconds默认3、范围1–10，不能传0；调度任务执行超时另设10秒。MQ生产者注册真实TransactionChecker后启动，Topic必须为TRANSACTION类型。

目标预算由类型化设置在受理时固定到run.pipeline_config，模型/工具发起和提交时重核；Token使用供应商适配估算器和安全余量，UTF-8字节预算独立限制存储/传输，不把字节数当Token。超过预算改为有界取证或明确停止，不截去关键条件继续调用。真实混合负载容量仍须单独验证；单轮预算耗尽明确FAILED，过期RUNNING中断且不自动付费重跑。每次真实模型请求及重试单独记账，缺用量/缓存/费用保留未知；创建动作草稿不新扣次数。

原件流、MinerU解析和Embedding按文件/批次另设读取预算，不能套用15秒状态查询超时。回执查询在新额度/新副作用之前；未知付费调用不自动返还次数，Redis不是账本。Redisson watchdog不提供外部恰好一次，锁持有线程finally释放，进程关闭释放客户端；锁丢失仍按数据库回执和OSS对账处理。

Sentinel以下阈值均为每实例初值，不是业务吞吐承诺；路由分组取明确白名单，例外组与普通组分开：

| 资源 | 初始规则 | 拒绝及恢复 |
| --- | --- | --- |
| Gateway登录入口 | 10 QPS | 429，Retry-After至少1秒；另走user账号/来源防刷 |
| Gateway新排障POST | 5 QPS | 429，先查原请求，日次数与队列预算另算 |

| Gateway其余公开API | 100 QPS | 429，权限及资源查询仍由后端核验 |
| Java调用user核验 | 并发32 | 超限/熔断503，不能用旧身份放行 |
| knowledge→AI状态 / 各所属Java OSS | 并发8 / 4 | 超限503或有限退避，持久业务事实保留 |
| 上述Java远端熔断 | 10秒窗口、最少20请求、技术异常比例50%、熔断10秒 | 半开探测，HTTP业务4xx及RPC输入/权限/状态拒绝不计异常；非幂等OSS调用不自动重试 |

Nacos不可用时保留最后有效规则，冷启动加载应用基线并暴露配置降级；禁止静默无限流。Sentinel的资源进入/退出必须覆盖真实调用及异步订阅/RPC生命周期，不能在创建Publisher或stub调用返回future时立即退出；技术状态按接口约定统计。Python内部入口限并发/队列，worker模型并发由Python预算保护。

## 6. 启停、故障与检查

Windows本机持续日志可使用与服务器同版的原生Logstash，直接读取应用JSON文件并以独立日志writer写入现有ES。程序使用官方Windows包并核对SHA512；配置/凭据/采集偏移/PQ保留原生用户配置目录，采集器诊断日志与下载暂存归项目.local，不能把唯一偏移或活动凭据放入可删除工作区。按四个Java应用及AI的API/worker/receiver分别固定输入路径和数据流，禁止日志正文覆盖路由。使用与服务器相同的字段白名单、脱敏、行大小和速率限制；拒绝的日志记录丢弃计数，不能宣称无限完整采集。ES知识写权限不授予日志writer。

该开发采集方式不需要公开新的Logstash网络输入。启用128MiB持久队列、64MiB死信上限、单管线worker及1秒sincedb刷新；本机监测API只绑定127.0.0.1。管线配置测试须实际加载并执行过滤器测试，退出码0但报告No configuration found仍算失败。Windows的path.config使用反斜杠转义路径，避免正斜杠盘符被URI解析为协议。采集器重启须保留偏移/PQ，核对重启前后的真实Run事件及Trace ID；日志语义仍是至少一次，不能以单次重启验证宣称恰好一次或灾备通过。服务器容器日志继续沿原只读文件采集方式。

本机七路文件输入的Java堆初值固定为1GiB，采用安装包默认堆容量，批量25；同时观察实际堆占用、GC、队列增长与采集滞后，不把能启动当作内存容量验收。256MiB及512MiB配置均在长时本机运行中发生堆不足，不能继续作为推荐值。堆上限不等于进程总内存，需为JRuby、线程、直接内存和文件映射保留空间；内存不足导致退出时保留原偏移与队列，恢复后沿日志原时间及Run身份核对补采。默认关闭自动heap dump，需诊断时另行配置受限目录和生命周期，避免包含凭据的转储写入项目根或公开制品。

start-server.sh从自身目录工作，默认启动最终基础服务，--application再启动应用；校验镜像、真实配置、挂载及网络，健康等待有界、失败非零退出。顺序为MySQL/Redis/Nacos/存储→RocketMQ与Admin→Java业务服务及AI API迁移就绪→AI receiver/worker→Gateway/Web；观测独立启动，不将Zipkin/Logstash可用作为业务readiness前提。停止先拒绝新流量/任务领取，停止并确认在途状态、保留数据，不删卷或自动回滚。

```bash
bash start-server.sh
bash start-server.sh --application
bash stop-server.sh
```

Nginx配置HTTPS、history、上传/Range及SSE禁缓冲；DESK_SESSION使用HttpOnly、Path=/、SameSite=Lax，生产Secure，写请求以X-CSRF-TOKEN提交user签发的令牌，同源CSRF与可信转发头分别核验。user受控初始化首名管理员，无默认口令，重复不覆盖。执行器/控制台/业务管理权限分开。

Java存活/健康与readiness分开，AI /health仅进程；不通过健康探测调用付费模型。knowledge的MQ/AI故障不关闭其数据库、资料查询等核心能力，但新索引必须取得半消息回执并提交本地事实才可报告已提交，不再具备Broker离线时确认受理的能力；上传的Redis/OSS资格在该动作边界检查。API双监听、receiver连接/最近受理、worker心跳/最老任务、PREPARING最老年龄、已提交但AI长期未受理/未收到取消、事务回查UNKNOWN/耗尽、消费积压/DLQ、XXL最后成功触发、Sentinel拒绝/规则来源、日志采集滞后、追踪丢弃和磁盘余量分别可查。独立受控检查入口输出安全指标；任务受理以RPC及持久事实核对，运行日志快照不代替实时数据库事实。

## 7. ELK与Zipkin运行

应用按实例目录输出逐行脱敏JSON，初值3天且每进程最多512MiB，有界异步队列满时记录丢弃计数。Logstash file input使用容器内绝对glob，每个输入独立持久sincedb，不用/dev/null；只读挂载日志源、读写挂载自身data，启用queue.type=persisted、PQ上限512MiB。只采活动JSON及未压缩轮转文件，采用rename轮转并保留足够采集窗口，验证不会误读压缩文件或重复整文件。一次性启动不能清空偏移/PQ掩盖积压。

Logstash输出logs-desk.<service>-<env>数据流，service段按系统设计白名单映射为不含连字符的名称，显式@timestamp、白名单映射和create写入；模板/生命周期在初始化时安装。初始保留7天、滚动50MiB或1天，日志容量目标5GiB并设置磁盘预警，生命周期清理有延迟，不能当硬磁盘配额。为采集设有界速率与丢弃统计，磁盘水位接近阈值先限日志写入、清理过期日志，保护知识检索；按真实混合负载调整CPU/堆内存/磁盘，不宣称共享ES没有资源争用。Kibana保存日志错误、耗时、任务/投递、限流及调度看板，运维账号只读日志；初始化管理凭据与运行凭据分开。

Zipkin使用STORAGE_TYPE=mem，设置MEM_MAX_SPANS=100000、Java堆初值256MiB及容器内存上限512MiB，按span上限淘汰旧数据，旧trace可能不完整；重启丢失历史。默认采样10%，专用验收100%，Java/Python exporter有界队列、批量及超时，无额外Collector。验证Java内部HTTP、跨语言gRPC、MQ生产/回查/接收→worker和问答Web→worker的traceId接续，包含未采样及exporter失败。追踪保留与业务审计无关，运维页仅私网可达，不保存用户正文、模型载荷、凭据或URL查询中的敏感值。

Windows开发应用输出本机JSON并直连Zipkin；持续集中采集按第6节使用原生Logstash及持久偏移。安全样例日志只验证格式和过滤器，不能代替实际进程日志的持续采集；不为开发机另造应用远端日志发送器。最终交付必须真实验收整条ELK及Zipkin链，不能以本地grep替代。

## 8. 备份与隔离恢复

暂停上传/发布/新任务受理及领取，停止XXL相关触发和MQ接收，等待在途业务/解析收敛或记录其未知依据。联合备份四个MySQL服务库及迁移/Session数据、xxl_job技术库、Qdrant完整snapshot/空间配置、数据库引用的OSS精确版本清单与原件摘要、Nacos配置/Sentinel规则、Broker数据/消费组配置及未收敛MinerU恢复依据。记录镜像digest、模型/Prompt、制品和备份时间，密钥独立保管，副本放独立存储；卷内快照和OSS版本控制不代替备份。

MySQL不提供跨存储一致快照。独立端口/账号/卷恢复，先关系事实及精确原件版本，再Qdrant及空间/ID/数量，从MySQL片段重建ES知识索引；跨Bucket新Version ID须受控映射。无Qdrant快照时按原空间重新Embedding并确认费用/可用性。日志及Zipkin不属于恢复业务必备数据，ELK配置/看板需要备份，Logstash偏移/PQ只能与匹配的原日志卷一起恢复。

恢复Broker或重放旧消息会重复交付，先核对kb_index_job提交/取消事实、半消息及AI任务/墓碑，再启用接收和生产者回查；禁止只以当前文档状态猜历史提交。Broker数据丢失或消息超预算时，管理员逐项核对后以replay-command沿原jobId/hash/operationId重放已COMMITTED的指令，已提交取消优先CANCEL，不扫描重发、不把PREPARING当已提交。AI已受理任务由本库worker恢复，取消墓碑防旧提交复活。不能只恢复knowledge旧快照再对接未回退的AI库；四库需同一停写恢复集合，发现摘要/任务不一致先阻塞核对。先恢复业务事务证明、已知任务/取消与远端解析依据，再开放发布和新尝试，问答不自动付费重跑。

恢复后核验客户开通范围、待分类及原受理快照、技术私有会话、state_version/事实更正、实际来源传递依赖、逐次调用未知、发布链、未完工单、CONFIRMED预约及reserved_count。旧问答不自动付费重跑，未完模型/工具调用对账为UNKNOWN而非成功。Redis不恢复活跃锁；确认旧上传者停止、未知对象收敛后再开放上传，新登录/AI预算在受控窗口重建，不当作新增权益。XXL先禁触发，校验BEAN/地址/token后补扫，避免恢复即执行示例或旧任务。隔离验证通过才开放写入，不默认删除现有卷和无关数据。

只读工具不连接OSS或删除对象，候选清单不能直接作为删除授权。AI原件校验临时文件由DESK_AI_RPC__ORIGINAL_DIRECTORY指定；开发默认位于项目.local/runtime/originals，生产须指定所属实例可写且有容量限制的临时目录，异常退出残留在确认进程停止后由运维核对清理，不进入镜像或备份业务原件集合。

## 9. 人工链初始化与隔离验收

user首次启动须显式配置`desk.bootstrap.enabled=true`、`organization-code`、`organization-name`、`username`及`password`。密码从所属服务受控配置提供，无默认值；已有服务商时重复初始化不覆盖账号或口令。首次登录或重置后必须改密；完成初始化后关闭bootstrap开关。三个内部调用方分别配置独立且至少32字符的ticket-token、knowledge-token、ai-token，CSRF使用独立secret。生产同时启用Secure Cookie和HTTPS同源入口。

user的`desk.identity.rpc`默认启用，host/port及ca-file、certificate-file、private-key-file由所属服务提供；缺少证书拒绝启动，不回退明文。AI使用`.env.example`登记的RPC CA、客户端证书/私钥及service-token；身份调用最多2.9秒、连接2秒、不自动重试。ticket/knowledge另按所属desk.support.rpc配置mTLS服务端；各自desk.ai.rpc配置独立客户端证书、AI目标及令牌。AI RPC入站按knowledge/ticket独立token白名单验证，出站身份/支持/知识使用其专用service-token。缺证书不回退明文，不能共用浏览器Cookie代替服务认证。纯人工动作不连接AI，只有采用草稿才延迟建立AI通道。

真实人工链验收入口为`.github/scripts/verify_application.py --work-dir <项目.local内目录>`。通过进程环境提供DESK_VERIFY_ISOLATED=true、DESK_VERIFY_HOST=127.0.0.1、DESK_VERIFY_PORT、DESK_VERIFY_USERNAME、DESK_VERIFY_PASSWORD、DESK_VERIFY_REDIS_PORT及可选DESK_VERIFY_REDIS_PASSWORD；实例须专用可销毁，数据库必须为空，脚本不接管非空库。先构建Java JAR并在desk-ai完成锁定安装及合同生成。脚本启动自有user/ticket/Gateway，临时双向TLS证书仅留.local，自动验收后关闭自有进程，不停止数据库或其他应用。CI的database任务先运行verify_database.py原生迁移/约束验收（含verify_ai_invariants.py的真实AI仓储执行权检查），再执行该入口。数据库验证另需--work-dir参数，同样只接管脚本新建的独占CI库，拒绝已存在的CI库。

隔离验收用静态服务发现验证Gateway与Feign的负载均衡调用，不连接Nacos、XXL控制台、Zipkin或共享业务库。期限扫描直接调用生产Service验证数据库行为，不据此宣称XXL注册/调度/回调已验收。真实外部组件及恢复的未通过项见阶段验收记录。

## 10. 持久执行与解析对账

按API完成迁移→receiver→worker启动。AI worker有独立解析收敛循环：业务FAILED/CANCELLED但解析仍ACTIVE时，沿原taskId/fileId查询及取消直至已知终态。MinerU上传响应未知不证明上传未发生，已知原身份优先续查；创建未知且没有远端ID时不自动重建任务。Markdown不连接MinerU。

仅当旧解析环境已隔离，并已取得可审计核对依据时，在desk-ai目录使用受控维护入口：

```text
uv run --locked python -m servicedesk_ai.reconcile_parser --job-id <原32位jobId> --operator <操作者> --evidence <核对依据> --confirm-old-parser-environment-isolated
```

该命令只将本库FAILED/CANCELLED、无远端ID且SUBMITTING/UNKNOWN的PDF解析状态登记为SETTLED，追加操作者、依据和核对时间；不改业务终态、不新建解析、不重写原摘要。已知ID必须走原任务收敛，不用该命令跳过外部核对。

上传响应未知沿原clientUploadId查询；新索引沿原clientRequestId查询，未知不换jobId。受控replay-command只重放已COMMITTED的原操作，已提交取消优先CANCEL。发布及恢复都重新核对当前双副本，不能仅看历史SUCCEEDED。预约容量始终由ticket事务确认，与MQ/Redis库存无关。

私有排障遇明确焦味、冒烟、鼓包、电火花等用户风险反馈先由规则停止并转人工，不依赖模型或检索可用性；否定和“是否/有无”的待答询问不作为阳性观测。上下文、调用数或总期限耗尽明确结束；新轮须由用户显式提交。配置、迁移、构建、业务联调及设备/生产验证分开报告，验证要求见[开发规范](开发规范.md#6-验证和交付)，本机验收记录不作为部署或恢复已通过的依据。

## 11. 目标系统发布门槛

本文件中的进程、预算与拓扑对应37张自有表（user 5/ticket 12/knowledge 5/AI 15，技术表另计）。真实开发环境已迁移并打通主要业务与Agent链路，当前进展及明确未验收项见根README；尚未完成领域效果门槛、生产交付及联合恢复，不能据迁移成功宣称可生产上线。旧命令仅操作其对应实现版本，完整步骤见[数据库初始化与迁移](../sql/README.md)。

先在隔离环境完成打印纵向链及VPN/办公软件边界；冻结模型/Prompt/工具/规程/索引空间和费用配置。工程故障注入、领域保留题集、专家审阅、真实设备及实际参与者试用分别提供证据；发布门槛集中见[系统设计](../设计/系统设计.md#12-验收与恢复原则)，不复制另一组可随意放宽的指标。

上线逐场景/客户范围开放，AI失败保留人工链。监测队列年龄、未知调用、运行停止原因、过期检查项、待核实草稿、来源撤回影响、可避免交接率和单位任务费用。告警不读取私聊正文；Run/Task业务审计和调用账目归MySQL，ELK/Zipkin不替代它们。

### AI任务预算与模型费率

AI的.env.example声明task_budget、chat_pricing及embedding_pricing。task_budget是单诊断任务跨Run的累计上限，每次模型意图预留和结果结算都核对；不能通过新轮重置。未知调用保留Token及已知费用预留，未对账不再次付费。Chat与Embedding分别配置每百万Token输入/输出费率、币种和policy_version；未知费率保持null，账目不能显示为免费。设置金额上限前须配置实际供应商费率，缓存费率缺省时保守按普通输入价计算。模板中的24次/96000 Token是当前开发默认值，不代表领域评测已验证充分。

PDF长任务以processing_config.total_seconds（至多600秒）为总体预算。MinerU健康、创建和取消成功不等于完整解析成功；取消沿原taskId/fileId收敛，未知结果不得换身份重新创建。公开样本须记录来源、许可、改动和摘要；本地排版的摘编PDF应与厂商原始PDF区分。
