# 前端规范

本规范规定 desk-web 的代码、类型、状态、请求和交互方式。通用工作方法见[开发规范](开发规范.md)，目录见[项目结构](../设计/项目结构.md)，业务机制见[系统设计](../设计/系统设计.md)，依赖见[版本约定](版本约定.md)。

## 1. 技术写法与职责

使用 Vue3、Composition API、TypeScript strict、Vite、Router、Pinia、Element Plus 与原生 fetch。业务组件使用 `<script setup lang="ts">`，脚本使用 .ts；单文件块按 script、template、style scoped 排列，TS/JS单引号、无分号，模板属性双引号，具体排版交给 Prettier。不关闭 strict 或用断言掩盖协议缺失。

| 位置 | 负责内容 |
| --- | --- |
| layouts | 导航、侧栏、内容区域及布局交互 |
| views、业务私有组件 | 协调页面数据、动作、草稿与展示 |
| 公共 components | 通过 props/emits/slots 提供稳定复用界面能力 |
| api | 端点、输入输出合同、序列化、响应与文件/流协议 |
| composables | 一个明确交互或资源生命周期 |
| stores | 需要统一所有权的跨页面共享状态 |
| utils、styles | 纯计算与转换、主题和基础样式 |

数据从 API 进入页面、组合函数或负责共享状态的store，再传给展示组件，用户动作通过事件返回负责交互的位置。API不依赖Vue、路由、store或UI库；公共HTTP不决定业务文案与跳转。认证由应用层协调，防止 HTTP→store→API 循环依赖。

页面私有代码靠近业务，跨业务且语义稳定后再共享，不引用其他页面内部实现。组件围绕独立职责拆分，不按行数切割，不把大页面搬进万能composable；纯函数不强行包装为useXxx，表格封装不默认接管权限、路由、删除和全部API。

## 2. 命名与合同归属

| 对象 | 写法 |
| --- | --- |
| 页面 / 组件 / 布局 | DocumentDetailView.vue / CitationList.vue / AppLayout.vue |
| API文件与函数 | documentApi.ts；getDocument、listDocuments、replaceDocument |
| 组合函数 / store | useDocumentList；authStore.ts导出useAuthStore |
| 业务合同 | 所属API目录的types.ts；DocumentUploadForm、DocumentVO |
| 类型与有限状态 | PascalCase；GenerationStatus |
| 变量、函数 / 布尔量 | camelCase / is、has、can表达含义 |
| 常量 / URL与CSS类 | UPPER_SNAKE_CASE / 有含义的kebab-case |

不用MyTable、CommonPage、data1等名称，不复制Java分层或I前缀。类型导入使用import type，路径大小写与文件一致；别名同时配置Vite和TS，不建立只为缩短路径的层层index转发。公共合同不能从大页面或store导出供全工程依赖。

## 3. 组件与响应式状态

props只读，编辑建立独立草稿，嵌套对象不能因浅拷贝仍回写父状态。defineProps/defineEmits使用明确类型，双向绑定约定v-model；组件ref用于聚焦、滚动等必要命令动作，不通过事件总线或操作他人DOM绕过数据流。

派生内容用computed，复杂模板表达式提取计算值或具名函数，渲染不发请求、不改状态。列表key使用稳定业务ID，不用会变化的下标；先过滤再渲染，避免同元素v-if/v-for。Element Plus采用显式导入，不假定已配置自动导入。

| 状态 | 主要维护位置 |
| --- | --- |
| 筛选、分页、弹窗、草稿、当前流 | 页面或所属组合函数 |
| 同一页面多个子组件共享 | 父组件或页面级组合函数 |
| 当前用户与跨页面必要偏好 | 职责明确的Pinia store |
| 可由已有状态得到的内容 | computed |
| 需分享或刷新恢复的查询条件 | 按需求使用并校验路由query |
| AbortController、DOM引用、计时器 | 创建者的生命周期，不能持久化 |

局部值用ref，紧密关联表单可用reactive；watch仅处理明确的请求、订阅或存储副作用，不用深度监听同步两份完整业务数据。Pinia使用Setup Store，状态通过storeToRefs解构，动作直接调用。退出、账号切换与身份失效清理所属用户缓存和订阅。

请求、定时器、监听、观察器、流读取器与Blob URL由创建作用域释放，使用watch清理、onScopeDispose或卸载钩子。资源切换结合取消信号、请求序号或资源ID隔离旧响应；旧请求finally不能清除新请求loading。轮询有停止条件、串行调度，不叠加未结束请求。

## 4. 类型、请求与错误

Form 表达客户端可写输入，VO 表达输出。合同就近放在业务 API 的 types.ts；UI 草稿或展示模型确有差异时单独定义，不复制后端 Entity，也不机械增加 DTO。后端使用普通 Java class 不要求前端改为运行时 class，前端仍使用明确的 TypeScript 类型描述 JSON 合同。

字段名、必填性、null、缺省值和有限状态对齐后端。更新时明确未提供、显式 null 和清空，不能把所有空值都删除，也不能把服务端决定的角色、状态和存储位置混入提交。输入按可写字段白名单构造，不直接把完整 VO 回传。不使用 any、全可选字段、任意索引或双重断言掩盖缺失合同；外部数据与 catch 使用 unknown 后收窄，request<T> 不能代替运行时校验。

状态使用有限联合和完整展示映射，未知值按合同提示或作为协议错误。业务 ID 使用 string，格式统一引用[数据库设计](../设计/数据库设计.md)。问答幂等键只为一次新请求生成，重试核对原操作时保留原键。版本与超出安全整数范围的值按公开合同使用十进制字符串，日期和带时区时刻分别处理，未知值不转换为0或当前时间。

| 边界 | 处理职责 |
| --- | --- |
| 公共 HTTP | 同源与认证支持、超时取消、HTTP及Result的code/message/data/traceId校验、类型化错误 |
| 业务 API | URL、方法、Form/VO 字段校验、序列化、文件和流协议 |
| 页面、composable 或 store | 当前交互的加载、草稿、结果、失败、结果核对与重试 |
| 应用认证协调 | 身份失效、用户缓存和订阅释放、单次跳转及合法站内返回 |

普通JSON的`Result<T>`只解包一次，业务API返回data有效载荷，不让页面重复判断包装。HTTP成功状态与业务码0同时满足才成功，1为系统异常；旧成功码200不再作为兼容成功值。src/api/resultCodes.ts集中维护SUCCESS、CONFLICT及前端实际判断的其他命名常量，不复制整套后端枚举或在页面散落数字，不按编号前缀猜HTTP状态。完整编号以[错误合同](../设计/接口约定.md#12-错误码与边界转换)为准。健康、文件、OpenAPI和SSE保持专用协议。公共 HTTP 提供类型化错误与失效通知，业务提示归交互层，跳转归应用认证协调。401、403、正常空结果、取消、超时、网络故障、协议错误和结果未知分别表达，不把失败吞成空数组。429展示稍后重试并尊重Retry-After，503区分依赖保护与身份失效，不触发登录跳转或自动重做副作用；上传锁忙409按原clientUploadId查询/重试。

索引add保留同一次clientRequestId，展示本地submitState/cancelState、AI是否已受理及独立执行状态。PREPARING表示准备未决，COMMITTED表示本地指令已提交，均不等于索引成功；原请求未知先查询原键，NOT_FOUND或RPC失败不能证明无在途消息。ABORTED是本次准备终态，新尝试须由用户显式发起，不能自动换键。仅成功且后端核验通过才可发布；replay-command仅供授权管理员重放已提交原指令，不是重新运行索引。浏览器不直连内部gRPC或RocketMQ，后端安全错误统一转换后展示。

管理普通 JSON 按[接口约定](../设计/接口约定.md#5-管理动作与网关归属)使用 POST 动作。分页、筛选、标识和版本放请求体，list/query 也携带当前 CSRF 令牌。页面按业务语义区分只读和写入，不能仅凭 POST 判定是否可自动重试。

请求有有限超时并保留调用方 AbortSignal。读取按实际需要防抖、取消或有限重试；有副作用的上传、发布、删除和生成不因超时、刷新或断线自动重放，先按幂等标识或原资源核对结果。URL 使用编码与 URLSearchParams，FormData 不手设 boundary，下载先检查错误类型，凭证只发送到同源可信接口。

## 5. 路由、表单、列表与文件

### 5.1 路由和身份

路由使用具名路由、必要 RouteMeta、业务页懒加载与嵌套布局，动态路由有实际需要才接入。history 模式由部署提供入口回退。身份来自后端当前用户合同，区分未确认、已登录、未登录和探测失败，不以浏览器标记证明登录。守卫与按钮只改善体验，后端逐次授权；登录返回只接受合法站内地址。

### 5.2 表单与版本

表单提供中文标签、提示、类型化规则、提交状态和服务端错误。前端校验改善体验，不能代替后端格式、权限或业务校验。新增使用明确默认值；编辑只复制可写字段，切换记录时重新初始化草稿与校验，后台刷新不覆盖正在编辑的内容。

提交期间防重复操作，失败保留输入，成功只清理本次已提交草稿，不删除等待期间的新输入。版本冲突以集中CONFLICT码及明确业务合同识别，保留草稿并提示重新读取，由操作者决定后续操作，不静默覆盖新版。公共标识/版本表单在JSON中仍是扁平字段，不因后端继承在前端建立嵌套对象或运行时Java式类。发布、替换、删除等按实际后果提供必要确认，不给所有点击统一加确认框。

### 5.3 列表和分页

分页字段、默认值和有效范围统一遵循后端[分页合同](Java后端规范.md#62-分页合同)，前端初始查询、分页控件和缺省处理使用同一规则，不在页面另定默认值。输入为 pageNum/pageSize，输出为 records/total/pageNum/pageSize；业务 API 验证完整合同，不把非法响应当空页。

列表区分首次加载、正常空结果、失败、刷新和加载更多失败。相同查询刷新失败时可以保留仍有效数据并提示；筛选或资源变化时不能把旧数据当新查询结果。筛选变化回第一页，清空后重查，排序变化重置相应页码；删除页内最后一项时校正页码并重新查询。

筛选、排序、分页和总数由数据库侧计算，前端不读取整库后截取。防抖、watch 与显式操作不能重复发送同一请求；请求序号或资源身份隔离迟到响应，旧请求 finally 不得清除新请求的 loading。

### 5.4 上传和原件

上传展示类型与大小提示、传输回执、后台阶段和最终结果，不伪造完成百分比，不从上传成功推断 READY 或发布。轮询串行执行，在终态、切换和卸载时停止；原件与下载使用受控地址，Blob URL 由创建者及时释放。

发布、替换、取消和删除按真实业务合同执行，成功后同步相关列表与详情，失败和结果未知分别提示。原件来源、物理页和可读性使用后端事实，不从模型正文推断地址或权限。

## 6. 问答流

读取和SSE解析归业务API，增量、订阅与资源切换归组合函数，正文和引用归组件。事件使用可判别联合，正确处理UTF-8分段、跨chunk事件、多行和缓冲；已知事件字段非法明确失败，未知扩展按协议处理。

断流或读完不能直接判定业务成功，完成事件与服务端持久化结果按合同核对。离页关闭订阅只表示本地停止读取，不代表后端取消；切换隔离旧事件，重返查询既有运行，不自动重发原问题。失败、取消、中断和待核对分别展示。

本项目运行时只展示真实阶段，校验正文及引用并提交终态后交付完整结果，不将阶段流描述为逐 Token 答案。用户在底部才跟随，向上阅读保留位置并提供回到最新；中文输入法组合态不误触发送，失败保留未确认提交输入。长会话优化不得静默丢弃内容，引用按PDF物理页、Markdown锚点/行区间及工单事件类型展示，仅使用后端真实定位。

## 7. 样式、内容与可访问性

同类页面保持布局与反馈一致，优先Element Plus，共享颜色、字号、间距和圆角用主题变量，局部style scoped；深度选择器限定包装范围，不全局覆盖组件库。Flex/Grid明确滚动区域，桌面、窄屏和移动视口保留关键操作；表格与原文在自身区域滚动。

表单有标签、图标按钮有可访问名称，键盘与焦点可操作，弹窗管理焦点，状态不只靠颜色，流式提示不逐token打断辅助阅读。用户、模型和文档内容作为数据，Markdown禁原始HTML并校验链接与扩展，v-html仅接受受控渲染结果；外链新窗口设置合适rel，不从模型正文推算资源地址或权限。

VITE_*、public与前端包视为公开信息，不存服务端密钥。Session不复制到localStorage/sessionStorage；聊天、证据与资料不默认持久化到浏览器，草稿与偏好恢复明确账号隔离和清理。安全Cookie由后端与浏览器协议管理。

## 8. 注释与测试

新增模块、导出API、组合函数、协议解析和复杂转换使用中文JSDoc与 `@author yangaobo`，必要时说明@param、@returns、@throws、单位、空值和资源释放。类型字段与props/emits说明非自明合同，不为简单ref、getter或点击处理器写机械长注释。

| 测试类型 | 重点 | 工具接入方式 |
| --- | --- | --- |
| unit | API边界、纯函数、状态与生命周期 | Vitest |
| component | props/emits、键盘、草稿与错误反馈 | 有用例时接入Vue Test Utils |
| integration | 页面、API、路由与store协作 | 按需要使用Vitest及网络替身 |
| e2e | 登录、资料处理、问答引用等关键流程 | 有真实流程时接入Playwright |

生产代码在src，测试在tests并按生产路径组织；fixture、mock和helper不进入生产构建。稳定夹具表达真实合同，不用随机或方便数据掩盖错误，不以私有函数、样式快照或mock证明后端授权正确。

API验证HTTP成功且code=0、非零业务码/HTTP失败、缺字段/旧成功码等非法响应、取消、超时与断网；查询验证旧响应和清理，操作验证防重复与草稿，流验证分段、断线、切换、终态及账号变化。修改前端按影响执行typecheck、lint、format:check、相关行为测试与build，命令以package.json实际脚本为准；仅文档变更检查合同与链接，证据随实施任务交付。

## 9. 办公IT支持交互

客户先描述问题，可选择支持项目或“不确定”，设备按需关联；四类服务显示支持条件，未知环境可留空，来源标签来自后端，不提交“工具已验证”等可信来源标识。未分类只承诺分流，不能展示AI已支持全部问题。客户开通日期影响新请求，已有工单履约/历史由后端判断，不根据设备期限隐藏。全局服务目录由系统管理员维护，客户服务资格由范围内客服维护；显示startsOn/endsOn、暂停/恢复及历史事件，写动作保留clientActionId和已有行rowVersion。首次受理耗时按接单/分派显示，不标成客服首次答复。

客户工单按本人及原组织，技术助手按本人及当前有权工单读取；转派只接续正式时间线，不加载前任私有对话。技术人员助手嵌入工单详情，明确区分用户反馈、人工记录、工具观测和模型假设，提供待答项、来源和工具安全状态；不展示隐藏思维链。建议执行须用户明确反馈才标已尝试，不从助手文本猜状态。

会话rowVersion、事实stateVersion和技术ticketVersion使用不同字段。事实更正带stateVersion及clientActionId，活跃运行时不可悄悄覆盖；工单变化提示旧建议过时，保留草稿并重新核对，不自动付费重跑或自动以新版本提交。需要用户回复时本轮已结束，显示待补充，不持续显示worker运行。

工单分类/环境、接单、转派、记录、解决和确认携带规定版本及动作键。CREATE_TICKET/ADD_RECORD/RESOLVE_TICKET草稿均须人工编辑确认，采用原ticket动作及sourceDraftId；创建草稿不新增模型等待。AI故障保留输入与直接提交入口。显示人工报告恢复、指导交付或转介结果，并区分客户确认与超时结单，旧迁移LEGACY_UNKNOWN显示历史原因/处理结果未知，不显示虚构修复成功。

预约只在已分类、具备现场资格且地点有效的工单中开放，设备可空。201返回CONFIRMED或REJECTED，未知响应查原clientRequestId，不展示待确认队列。工单地点修改前处理活动预约，设备地点变化不重写地址；到访结束不自动标已上门，以实际登记为准。

资料上传支持PDF/UTF-8 Markdown，前端提示各自预算及适用规则。使用clientUploadId，未知结果查原回执；同源knowledge预览下载，不引入OSS SDK/STS/永久地址。Markdown禁原始HTML与自动远程资源加载，来源定位不伪造页码；上传、索引和发布分别展示。

技术会话反馈不显示共享开关，无帮助结果显示RECORDED且不显示等待知识管理员处理，知识管理员不能展开；客户自助反馈共享默认关闭。脱敏案例只通过人工整理的资料原件审核发布，页面不提供自动分享整段工单/私有聊天的捷径。
