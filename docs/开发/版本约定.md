# 版本约定

本文定义目标工具链、依赖、组件与模型空间。版本集中由构建声明、锁文件和镜像定义管理，文档说明选型和升级边界。模块职责见[项目结构](../设计/项目结构.md)，运行操作见[部署说明](部署说明.md)。

## 1. 工具链

| 工具 | 统一基线 | 管理方式 |
| --- | --- | --- |
| JDK | Java21，至少21.0.6且低于22 | Maven Enforcer；CI 与开发使用同主线 |
| Maven | 3.9.9及以上3.x | Enforcer；镜像构建固定3.9.9 |

| Node | 24.22.2及以上24.x LTS | package engines、CI 与构建镜像 |
| npm | 11.19.1及以上11.x | packageManager 固定11.19.1，npm ci |

common按实际公共类型声明Validation API、Jackson、Swagger注解及编译期Lombok，不依赖应用starter；根集中管理版本不表示向全部子模块添加依赖。optional也不能代替应用装配边界。springdoc只在MVC应用启用，Java文档目标为OpenAPI3.0；Python沿FastAPI实际生成版本，不安装Java文档组件，开关与网络约束见部署说明。

框架传递依赖遵守同一管理树，升级先看有效 POM 和 dependency:tree。MyBatis-Plus 使用 spring.service 的 IService/ServiceImpl 包，不照搬参考项目旧包。Flyway 选用同属11.x且覆盖 MySQL8.4 的版本，core/mysql 不拆版，不引 PostgreSQL 数据库适配。

gRPC/Protobuf在根POM独立集中管理；api按生成类型的实际编译需要声明库，传输、health和客户端生命周期归业务应用。grpc-netty-shaded隔离应用传输的Netty，但不保证Protobuf/gRPC传递树自动兼容；与RocketMQ SDK、common-protos及Boot的管理结果一并核对有效POM、重复类及实际RPC/消息互通，不局部排除到编译通过就算完成。

Alibaba2025.1 对应 Boot4/Cloud2025.1，不与本文组合混搭。Nacos 配置使用 spring.config.import，不使用旧 shared-configs、extension-configs 或隐式应用名加载。服务发现、配置监听和规则数据源分别配置与验证。

XXL-JOB3.3.0 与 Boot3.5/Spring6 同系，但其传递 Netty 与项目 BOM 可能不同，接入必须验证收敛后的注册、触发、回调、日志和关闭。不能为某个执行器局部混装两条 Netty 主线，也不能因发行号更高直接切换 Boot4/Spring7 依赖。

Redisson使用独立客户端API，避免starter替换user的Lettuce连接工厂或引入不匹配的Spring Data Redis适配；不使用redisson-all聚合包。其Netty/Jackson与根BOM收敛后验证Redis认证、watchdog、抢锁超时、锁丢失和关闭。[Redisson Spring集成](https://redisson.pro/docs/integration-with-spring/)与[锁合同](https://redisson.pro/docs/data-and-services/locks-and-synchronizers/)仅为API依据，不能代替项目联调。

Java生成stub编译使用javax.annotation-api1.3.2，由根POM管理；Feign采用Cloud管理的feign-java11传输并保留LoadBalancer装配，以保留401错误正文。前端协议回归使用Vitest5.1.0，锁定于package-lock.json。

业务访问采用 mysql+asyncmy，迁移采用 mysql+pymysql；只管理 AI 所属库。解析器独立镜像，不把 MinerU、Torch、CUDA、Docling 或 PostgreSQL 驱动塞入 AI Web 环境。固定业务阶段使用普通类型化 Python，不预装无消费者的流程框架。

RocketMQ索引Topic明确message.type=TRANSACTION，沿原业务任务事实回查，不创建NORMAL类型的同名Topic或另设outbox投递器。Java SDK须验证半消息、显式本地提交/回滚、TransactionChecker注册与重启回查；Python消费已提交消息，无需实现生产事务协议。依据[事务消息合同](https://rocketmq.apache.org/docs/featureBehavior/04transactionmessage/)，实际回查参数及故障预算见部署说明。

## 5. 模型和检索空间

| 能力 | 合同 |
| --- | --- |
| 排障回答 | qwen3.8-flash，关闭思考，初始 temperature=0.2、最大输出2048 Token |
| Embedding | text-embedding-v4，1024维、float，每批最多10条 |
| 向量 | 文档和问题同模型/预处理，Cosine，精确过滤查询 |
| 融合 | ES 与 Qdrant 各最多50候选，RRF 的 k=60，最终最多8片段 |
| 模型接入 | 百炼 OpenAI 兼容地址，与账号地域和密钥匹配 |

排障工具调用使用同一百炼模型适配，已有真实tool-call和领域工具链分项验证。最终公开结果由DiagnosisResult生成严格JSON Schema（response_format=json_schema、strict=true），再由同一Pydantic模型校验；不因模型输出非法而放宽为任意对象。Prompt、工具Schema、规程解析及上下文策略版本写入运行配置，不引入第二套Agent框架或升级无关依赖。

每批验证数量、维度、有限值和非零向量，不截断向量。不同模型即使同维度也不能混空间。vectorSpace 固定模型、维度、预处理及配置版本，任务和评估保存请求/响应模型标识、Prompt及配置摘要，不存密钥。

更换回答模型不重算资料向量；更换 Embedding/维度/预处理需新空间和受控重建，发布修订按知识生命周期切换。客户建单草稿使用确认事实模板，技术草稿取源运行已有校验结果，创建草稿不额外调用模型；供应商API名不是包版本，不承诺底层权重永不变化。百炼托管应用/知识库、Qwen 本地推理及 Spring AI Alibaba 不属于本项目实现路径。

## 7. 版本源与变更流程

| 对象 | 唯一版本源 |
| --- | --- |
| Java BOM、库及插件 | 根 pom.xml，模块声明真实消费者 |
| Python 解释器/直接依赖/工具 | .python-version、pyproject.toml |
| Python 完整解析 | uv.lock |
| 前端/Node/npm | package.json、package-lock.json |
| CI | .github/workflows 中的实际入口 |
| 跨语言协议及生成工具 | desk-api/src/main/proto唯一源；Java工具由根POM、Python工具由pyproject.toml/uv.lock固定；.github/scripts统一编排生成与打包 |
| 镜像与部署 | .github/docker 的构建定义、deploy/compose.yml 及交付 digest |

CI 使用 checkout@v4、setup-java@v4、setup-uv@v6、setup-node@v4 作为工作流基线，具体工具版本依本文件，Action 维护标签与制品摘要分开管理。runner 标签浮动，不当作固定容器环境证据。

升级先核对发行、支持周期、兼容矩阵、API/peer、传递依赖、原生轮子、JSON、数据库迁移、索引及恢复，再同步版本源、锁、CI和镜像并验证。纯文档或业务任务不附带无关升级。正式交付固定镜像摘要、模型/空间和制品标识，重建仍核对依赖和供应商变化。
