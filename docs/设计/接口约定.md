# 接口约定

本文维护协同服务台的线协议。业务动作见[系统设计](系统设计.md)，字段与持久化约束见[数据库设计](数据库设计.md)，Java/Python 类型归属见[项目结构](项目结构.md)。公开合同及消费者随改动同步，当前已验证的运行范围见[项目 README](../../README.md#5-当前实现与本地检查)。

## 1. 基础协议

浏览器仅访问同源 Gateway 的 `/api/v1`，下游保留完整路径。Java↔Java采用OpenFeign + HTTP/JSON，内部`/internal/v1`仅私网；Java↔Python采用gRPC + Protobuf独立私网端口，均不经Gateway转发。跨服务可靠异步指令统一RocketMQ，协议不按语言另造消息系统。UTF-8 JSON 字段 lowerCamelCase；持久化 JSON 快照使用数据库设计约定的 snake_case，不能直接当公开 VO 返回。

### 1.1 普通JSON响应

普通JSON使用`Result<T>`，Java类型归common/base，Python按相同字段维护自身模型：

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "id": "7f8913a24e1c4e5bb183370ca032d9c8",
    "rowVersion": "0"
  },
  "traceId": "服务端链路标识"
}
```

code为整数，0是唯一成功码，1是未预期系统异常。message是安全中文说明，不作为前端分支条件；错误与无数据成功的data均保留null，不能全局忽略null。traceId由服务端创建或接续可信上下文，成功和失败均有值，不用业务ID代替。普通JSON须HTTP成功状态且code=0才解包成功；文件、健康、OpenAPI、SSE及gRPC保持各自协议，不包Result。

本节是Java、Python、Gateway和前端共同遵守的编号登记。数字大小不表示严重程度，不按前缀推断HTTP状态；以下为目标合同，不代表代码已经迁移。

已登记编号全局唯一，0/1保留，不用负数或HTTP状态直接冒充业务码。已发布编号不回收、不复用、不改变含义。新增项先登记所有者、语义和边界映射，再实现并同步实际消费者；Java/Python协议检查比较定义及映射，不靠全仓数字搜索推断重复。客户端只集中维护实际判断的常量，不能比较message。

ErrorCode只有code()/message()，BusinessException不携带HTTP状态；Java的HttpErrorMapping、RPC适配器和Python异常处理分别显式映射。正常绑定错误为400/1001，Python输入约束错误保留422/1001；已知框架错误保留原状态、Allow/Retry-After等必要头，不能把416/429/503退化为参数错误。未细分框架4xx采用1001、5xx采用1并保留其真实状态；未知本地业务错误类型及异常统一500/1，不回显任意自定义消息。

内部调用先区分用户失效和调用服务认证失败：只有可信user会话合同明确2001/2002才触发浏览器退出；TLS、服务凭据、上游连接及未知协议错误转换为当前依赖故障，不能直接透传上游401注销用户。已登记且合同允许的业务拒绝可保留稳定code；未登记上游载荷按502/1012安全处理，日志关联原追踪但不转发内部堆栈。gRPC的RpcErrorDetail.code复用同一非零数字空间，成功message不附错误码。

任务error_code/last_error_code/failure_code、预约resultCode和MQ command是持久或专用协议事实，不是Result.code，不因数字响应码调整而迁移历史数据。预约REJECTED、排障无证据和已取消结果可以是成功查询到的业务资源，不能混同接口调用失败。

5003只用于诊断任务跨轮累计预算拒绝。单Run上下文、模型/工具次数、Token或墙钟预算不足记录为持久诊断`EXECUTION_BUDGET_EXCEEDED`；索引模型调用预算不足记录为`INDEX_BUDGET_EXCEEDED`。它们不新增HTTP业务码，不伪报环境变化或依赖不可用。实际调用已经发生时先保存真实用量，再停止交付超预算结果；历史账目不回写成零。

### 1.3 HTTP状态与结果语义

| HTTP | 语义 |
| --- | --- |
| 200 / 201 / 202 | 查询或动作成功 / 创建成功 / 已持久受理待执行 |
| 400 / 422 | 格式/绑定不合法 / 输入约束不合法 |
| 401 / 403 / 404 | 身份失效 / 动作无权 / 不存在或资源不可见 |
| 409 | 状态、版本或同键异义冲突 |
| 413 / 415 | 文件或请求过大 / 不支持的类型 |
| 429 | Sentinel流控或主体日次数用尽，安全返回Retry-After |
| 500 / 502 / 503 / 504 | 本服务故障 / 上游协议故障 / 必要依赖不可用 / 上游超时 |

按用例统一选择隐藏无权资源的404，不通过列表、详情、引用或错误消息泄漏其存在。HTTP失败不能用code=0，业务失败不能包成成功空列表。已持久保存的申请结果由资源status/resultCode表达，创建/查询该结果资源本身可返回201/200；预约REJECTED必须明确展示未取得名额，不能因HTTP成功显示预约成功。接口输入、权限、资格和技术失败仍使用相应错误。

## 2. 标识、数值与分页

业务 ID、clientRequestId、clientActionId、clientUploadId 都是32位小写十六进制字符串；框架 sessionRef 与 claimToken 是带连字符 UUID，供应商 ID 按其协议。资源所有者生成业务 ID，调用方只生成自己的幂等键，不能指定服务器资源 ID 绕过所有权。

rowVersion、taskStateVersion、diagnosisContextVersion、ticketRowVersion、ticketEventSequence、authVersion、total、Token总量等bigint 公开为非负十进制字符串。pageNum/pageSize、有限候选数与数据库integer序号为JSON整数；消息/事件bigint序号为十进制字符串。本系统没有客户金额结算；模型estimatedCost使用十进制定点字符串及currency，不将Token/版本或费用隐式转浮点。未知用量/费用为null，不写0。

时刻使用含时区 ISO8601，例如 2026-11-10T02:00:00Z，前端按 Asia/Shanghai 展示；业务日期 YYYY-MM-DD 与时刻分开，截止由服务端判定。字段缺失、null、空串、清空和不修改按动作说明，不能统一删除空值。公共IdForm/VersionForm/IdVersionForm只是兼容输入的复用方式，不能改变路径ID、jobId/documentId、可选版本或幂等键字段名；有差异的动作用具名Form。

分页统一遵守[分页合同](../开发/Java后端规范.md#62-分页合同)：pageNum/pageSize 默认1/10，每页1–100，输出 records/total/pageNum/pageSize，total 为字符串。排序包含唯一键，筛选与授权同时应用于列表和总数，非法分页拒绝，不读全量再截页。

## 3. 身份与内部认证

浏览器使用HttpOnly Cookie DESK_SESSION，Path=/，生产Secure、同源和SameSite=Lax；Session不写浏览器存储。CSRF请求头固定X-CSRF-TOKEN，令牌值由user签发并在轮换后重新获取，不把具体令牌硬编码或持久化到数据库。user 使用 Spring Security/CSRF 与 JDBC Session，登录后轮换会话，改密/角色/范围变化通过 authVersion 使旧身份失效。强制改密期间只开放必要身份、CSRF、改密和退出。

写请求含 CSRF 头，管理 list/query 虽只读也属于 POST，照样校验。获取令牌、登录、退出和会话轮换遵循同一同源流程。Cookie 只交身份核验，不持久化或转发给无关业务依赖。

| 公开路径，均在 /api/v1 下 | 方法 | 合同 |
| --- | --- | --- |
| /users/auth/csrf | GET | 返回令牌与约定请求头名称 |
| /users/auth/login | POST | username/password，校验 CSRF，成功建立会话，不返回认证 Cookie 值 |
| /users/auth/me | GET | 当前身份、角色、必要范围、需改密标记与版本 |
| /users/auth/password | POST | 当前口令与新口令，成功失效旧会话并重新登录 |
| /users/auth/logout | POST | 失效当前会话，重复退出遵循安全幂等 |

Gateway 删除外来身份、角色、客户范围及内部认证头，不把浏览器提供的 actorId 当可信身份。Java/Python 业务入口通过 user 内部核验取得当前身份，再执行本服务资源授权；核验失败拒绝操作，不能回退旧权限缓存。

内部访问先验证调用方凭据、服务白名单和允许用途，再核验用户上下文。每个调用方独立凭据，运行配置提供并可轮换，不能把所有服务共用一个全权令牌。内部 DTO 中 ownerId/customerId 本身不是用户证明。外部调用不位于数据库长事务内，提交时校验本地状态/版本，交付时复核当前权限。

ActorRef仅含ownerId、sessionRef和authVersion，不能把调用者提交的角色/客户范围当权威。Java资源服务经user内部HTTP重核该引用，AI资源服务经user RPC重核，再执行本服务授权。后台索引GetStatus和ReadOriginal按服务白名单及任务关系授权，不依赖浏览器Cookie；requestedBy仅审计，不提供用户权限。原Cookie只允许出现在user核验请求，不写日志/数据库或继续转发。

user身份核验可有HTTP及RPC两个入口，均转换到同一Service和规则；其他相同用例亦如此，不能复制认证/状态判断。身份依赖失败拒绝操作。预约退出浏览器不会撤销已确认履约，排障运行及交付仍复核原会话/认证版本。

Java/Python从desk-api同一份.proto生成协议类型；HTTP、RPC和消息各按唯一合同维护。实体不跨服务，持久化JSON不是Protobuf编码，供应商API继续按其HTTP/SDK协议。

## 4. 幂等、版本与结果未知

每次新动作生成一次键，重试/查回执复用原键。服务在当前授权内先查回执，同键同语义返回原结果，同键异义409。摘要使用规范化可写字段、动作和必要版本，不将时间戳/traceId 之类传输差异纳入业务语义。只有新的业务尝试才使用新键。

| 动作 | 键及范围 | 查询/重放结果 |
| --- | --- | --- |
| 建单 | requesterId + clientRequestId | 原 ticketId；sourceDraftId 另有唯一约束 |
| 工单及预约人工动作 | actorId + clientActionId | 原sd_action_receipt；建单/预约clientRequestId映射为统一动作键，draftRootId全局唯一采用 |
| 目录/客户资格维护 | actorId + clientActionId | 原it_service_event及目标id，已有目标按当前有权资源读取 |
| 诊断任务动作/问题回复 | taskId + actorId + clientActionId | 原ai_task_event、结果ID及taskStateVersion |
| 预约受理 | ticketId + clientRequestId | 原 bookingId 和当前状态 |
| 上传 | createdBy + clientUploadId | 原 documentId；文件/元数据摘要一致 |
| 运行/草稿修订 | ownerId + clientRequestId，分别唯一 | 原runId或draftId；草稿编辑产生新修订而非覆盖 |
| 索引提交请求 | requestedBy + clientRequestId | 原jobId及本地准备/提交状态，同键不同文档/版本/输入冲突 |
| 索引指令 | 固定 jobId + 不可变信封摘要 | 原任务和指令结果 |

人工动作带 rowVersion。重复已提交动作先返回回执，新动作再比较当前版本和状态；不能通过自动重新加载新版本绕过冲突。响应未知、网络超时、断流及502/503/504都不能证明未执行，先查询原键或资源，再决定显式重试。只读 POST 可有限重试，有副作用动作不能按 HTTP 方法笼统重试。

request-information、wait-external及follow-up提交非空content（最多1000字符）和followUpAt（带时区ISO8601），取得工单锁后以数据库UTC时刻核对未来期限。end-wait提交非空content（最多5000字符）；两种等待仅当前有权处理人可结束或续期，客户补充仅结束客户等待。每次进入或续期递增waitCycle；结束/取消清空当前等待字段，保留事件。扫描只给处理人发送内部跟进提醒，同轮最多一次，不改变诊断环境版本或宣称已解决。

现场信息为工单字段，修改须无活动预约；设备后续地点不回写。resolutionType为RESTORED/GUIDANCE/REFERRED，未分类只能REFERRED；转介须公开原因和去向。新CLOSED返回closureReason=CUSTOMER_CONFIRMED或CONFIRMATION_TIMEOUT；旧迁移记录无法判定时可返回LEGACY_UNKNOWN，前端显示“历史原因未知”，不接受新业务输入该值。旧处理类型同样可LEGACY_UNKNOWN，不能把超时当确认恢复。工作台首次受理指标以firstAcceptedAt/acceptanceDueAt/acceptanceOverdueRecordedAt表达，按接单/分派计算，不宣传为首次客服答复或合同SLA。

人工动作带规定版本和原键，草稿可选；sourceDraftId、sourceDraftRootId和contentSha256同空同有；根标识仅用于本地回执对账，新动作必须匹配本次内部RPC校验结果。若存在sourceDraftId，先查本动作或同草稿根采用回执，再经ValidateDraft校验用途、目标、期限和版本。同一草稿根不同最终语义冲突，同义返回既有结果，不重复写事件。草稿不会替代接单/当前处理人/内部备注权限。公开详情不包含INTERNAL、私有助手对话或受限来源；冲突保留输入，不自动读取新版本重新提交。

浏览器提供的草稿根与合法内部证明不一致，返回409/code=1004；内部证明缺少合法身份、内容摘要失配或证明期限不符合合同，才返回502/code=1012。用户替换确认参数不能被误计为AI依赖故障。

### 6.1 人工链的公开投影与审计


`POST /admin/service-item/events`与`POST /admin/service-entitlement/events`均位于`/api/v1`下，输入为id、pageNum、pageSize，带当前CSRF。目录变更审计仅系统管理员可读；资格审计仅有当前客户范围的客服可读。SERVICE_AGENT可以读取全局目录以选择开通项目，但不能创建或修改目录。

## 8. 知识、原件与索引

有权客户或服务人员通过GET /api/v1/knowledge/documents、/{id}、/{id}/file 获取有权资料、详情和原件。请求上下文提供serviceItemId、可选deviceId及具名环境，或已授权ticketId/历史runId引用；历史引用经EvidenceContextService/ResolveContext只核对上下文关联，knowledge再按HISTORY_REVIEW核验当前访问权和历史阅读资格，普通换版只标过时；其他用途经ticket核验支持范围，不接受任意jobId扩大范围。技术助手会话本身不是知识管理员读取工单的凭据。

上传multipart固定两个part：metadata为application/json，内容为clientUploadId、seriesId、contentFormat、资料字段、适用规则及可空procedureDefinition；file为原件字节。contentFormat为PDF或MARKDOWN；PDF至多20MiB，UTF-8 Markdown至多1MiB，校验媒体类型和内容，文本不允许自动加载远程资源。适用规则最多50条，服务项目必填，其余型号/系统/软件精确条件可空，空表示该规则不限制。knowledge 校验和上传 OSS 后提交修订，返回 documentId/clientUploadId。响应未知用管理 document/query-upload，输入仅原 clientUploadId，当前上传者和权限范围查询。未找到只表示无可见已提交回执，不证明 OSS 没有在途写入；保留原键和文件，不自动换键。

原件由 knowledge 授权后按数据库固定的 Bucket/Object Key/Version ID 流式返回，不暴露这些内部定位，不返回 OSS 凭据、STS 或永久地址，不重定向 OSS。支持有界 Range 与标准206/416；错误在流提交前返回安全 JSON，提交后中断并记录。文件名仅展示，不能成为磁盘/对象路径。

规程仅通过资料上传metadata.procedureDefinition创建，查询随document详情返回。POST /admin/document/validate-procedure输入id、rowVersion、clientActionId，仅DRAFT允许新校验；先查原动作事件，合法重放优先于状态/版本，校验不可变定义、原文定位及安全前置条件，返回procedureSha256和验证标记并写文档事件；失败不保存通过标记。定义有误重新上传新修订，无原地update或独立发布接口。发布在已有资料动作中检查procedureValidatedSha256等于procedureSha256。人工案例以Markdown原件提交，sourceReviewNote记录核对人、确认时间、材料使用依据及结果来源；knowledge不自动查询原工单或私聊。

规程公开JSON使用schemaVersion、applicability、requiredFields、checks、stopConditions、handoverConditions；每项检查使用checkKey、roles、instruction、answerSchema、requiredFields、prerequisiteCheckKeys、prerequisiteAnswers、riskLevel、stopConditions、sourceLocator。prerequisiteAnswers可省略且默认空列表，至多20项，每项为checkKey和非空allowedValues列表；只能约束已列入prerequisiteCheckKeys的较早CHOICE检查，允许值必须来自原选项，引用和值均不得重复。所有条件按AND核对；前置执行过但实际答案不在允许集合中时，不得提交该操作。旧修订缺省只保持原执行前置语义，不能推断其文字条件已结构化；条件纠错须新建修订，不修改已发布定义。sourceLocator的PDF形态为kind/pageNumber，MARKDOWN形态为kind/anchor/lineStart/lineEnd。answerSchema固定schemaVersion、kind、options、maxLength和可空minimum/maximum，不接受任意JSON Schema。环境字段和停止条件代码遵守数据库设计的宿主白名单；未知键拒绝。资料详情同时返回可空procedureDefinition、procedureSha256、procedureValidatedSha256、procedureValidatedAt、procedureValidatedBy。

KnowledgeSource授权结果可携带procedureSha256及procedureCheckKeys作为可读规程的元信息。ReadProcedure返回同一固定修订的KnowledgeSource、definitionSha256和最多64KiB的UTF-8定义JSON；AI先校验摘要和有限schema，再选择指定检查登记PROCEDURE_CHECK来源。read_evidence输入chunkId、expandSection和字符offset，模型只能选择本轮候选或已返回的分段游标；每次读取重新核对资料授权。返回previousSectionId/nextSectionId与sectionPart/sectionParts，不把单个分段标为整个章节。load_procedure输入documentId/checkKey，不允许模型任意枚举修订。

search_knowledge的sourceType是可选知识分类，默认不筛选；厂商发布的排障指南并不自动属于OFFICIAL_MANUAL。搜索预览登记METADATA，工具回执usageKind=METADATA、complete=false、readFromOffset=0，不返回正文nextOffset；即使短预览覆盖片段全部字符，也不取得完整阅读资格。首次read_evidence从offset=0开始；叶片展开到父章节改变字符坐标，携带非零offset时拒绝为INVALID_ARGUMENT。正文登记CONTENT，只能使用正文回执中的chunkId和nextOffset继续阅读；同摘要、同片段从0连续覆盖末尾才满足该片段完整性。标题、署名或许可完整阅读不证明技术结论成立，仍需核对相关技术正文。

read_task_context在已绑定服务项目的排障任务中注册，咨询无此工具；其协议开销在初始上下文选取前计入预算。仅当所需记录未提供时补读，不重复读取已给出的检查反馈。输入section（FACTS或CHECKS）、可选beforeId、可选query和limit（1至3，默认3）。query按字面子串匹配，SQL通配符被转义；不接受taskId、客户或其他范围。返回records、hasMore、nextBeforeId，以ID降序续读。事实附factId、原来源类型、正文sourceNumber及historicalEnvironment；检查附原提议Run、版本、状态、实际人工反馈及feedbackSourceNumbers。读取前后核对受理任务版本，事实按该版本过滤更正链；工具事实和历史检查继承原根来源并重新授权。旧环境记录显式标为历史，旧检查指令不能替代当前完整审核规程。假设的支持/反证factId必须属于本轮已读取的FACT/CONTENT来源，再核对任务内有效性；仅在用户文本提及ID不算读取。

当本轮来源已定位PROCEDURE_CHECK时，最终模型输出使用ProcedureResult；历史METADATA不提供可选操作，必须先读取完整CONTENT才能选CHECKS。nextAction是三种互斥对象的联合：CHECKS包含1至5项selections，每项只含sourceNumber；CLARIFY包含checkKey、question、dependencyFields和previousCheckId，dependencyFields须非空且仅含本轮已读规程要求的未知环境字段；模型Schema与最终校验共用缺口计算，已知条件齐全时不提供CLARIFY分支，checkKey不得复用已读审核检查键；CONCLUDE包含ANSWERED、INSUFFICIENT_EVIDENCE或HANDOVER之一的answerType，以及可空feedbackSourceNumber；仅ANSWERED必须绑定本轮CONTENT人工恢复反馈来源，其余必须为空。ProcedureResult不接受text，公开text由宿主生成。联合直接进入模型Schema，同一来源不得重复选择；操作和澄清不可能同时成为合法结果。宿主把CHECKS转换为ANSWERED检查建议，把CLARIFY转换为CLARIFICATION，CONCLUDE保留明确结论。用户复测报告恢复必须引用当前环境最新有效CHECK反馈：USER消息与任务对应、检查为ANSWERED、来源checkId/rowVersion与持久行一致、执行为PERFORMED且outcome为RESTORED_REPORTED，并且无未解除风险。准备输出及最终锁任务事务内均核验；仅完成操作、旧环境恢复或较早恢复反馈不能通过。恢复说明明确为用户报告，不能冒充现场实测。HANDOVER只表示需要人工接手，不表示正常结束对话。

宿主仅接受本轮CONTENT规程来源，从不可变定义填入checkKey、instruction、answerSchema、文档身份及强制环境依赖，并补齐引用。审核检查的previousCheckId由宿主从同任务同键的最新可复查实例绑定，新检查为空；模型不能指定其他检查为前驱。最终Schema将引用编号和假设事实ID限定为本轮CONTENT来源；操作候选进一步复用提交规则核对当前任务状态、角色、环境和前置答案，空候选不提供CHECKS分支。被排除的操作证据仍可用于解释或交接，来源正文不因此删除；固定拒绝原因输入模型，读取失败和版本变化立即停止。供应商约束不能替代最终锁内校验。最终仍经角色、环境、前置答案、停止条件和重复检查校验。普通完整知识路径使用RunResult。两种路径最终均按同一RunResult持久化及返回浏览器，模型选择合同不新增HTTP接口、持久表或自动执行能力。

资料安全动作 `document/withdraw`、`document/revoke-access`、`document/restore-access` 均提交 `id`、`rowVersion`、`clientActionId` 和非空 `reason`（最多1000字符）。在当前知识管理员授权内先查原动作回执，同键同义返回提交时资料快照，同键异义冲突；再执行状态和版本判断。风险撤回仅用于已发布过且未撤回的修订；访问恢复不改变发布状态。页面收到回执后重新查询当前详情，不能把历史回执当最新版本。安全动作原因与前后状态写入同一资料事件事务。

### 8.1 索引事务消息

SUBMIT/CANCEL只经RocketMQ事务消息投递；跨语言RPC只查询任务及读取授权原件，不提供第二条索引提交/取消入口。

| 消息项 | 固定合同 |
| --- | --- |
| Topic / 类型 | desk-knowledge-index-command-{env}，TRANSACTION事务消息 |
| 生产者 / 消费组 | knowledge / desk-ai-index-command-{env} |
| 业务键 | jobId；operationId标识本次指令操作；Broker messageId/transactionId仅诊断 |
| 信封 | schemaVersion=2、command、operationId、jobId、documentId、attemptNumber、contentFormat、fileSha256、requestedBy、processingConfig、requestHash |
| 追踪属性 | 受控traceparent/tracestate，与业务信封分开 |
| 大小 | JSON载荷最多64KiB且不超过Broker限制；不放原件、正文、URL、Cookie或密钥 |

requestHash覆盖schemaVersion、jobId、documentId、attemptNumber、contentFormat、fileSha256、requestedBy和规范化processingConfig，不含command、operationId、requestHash自身及追踪。同jobId输入不可变；SUBMIT的operationId=jobId，CANCEL使用本次准备记录的cancelOperationId，已提交指令重放沿用原operationId。CANCEL也携带完整输入。contentFormat为PDF/MARKDOWN且与原件元信息一致，processingConfig仅受限版本化解析/模型空间/切片/预算，不接收脚本。v2是目标信封，旧v1没有该字段；若存在实际v1任务/在途消息，迁移前盘点并保留原摘要的PDF解码与重放能力，完成旧任务收敛和保留窗口验收后才能退役，不能把旧jobId重新算成v2摘要。当前producer/receiver/worker已使用该v2合同，具体业务验证以当前代码及隔离回归结果为准。线JSON lowerCamelCase与持久JSON snake_case显式映射，MQ不因内部RPC使用Protobuf就改为另一套未定义载荷。

knowledge具有环境Topic生产权限及事务回查处理器，AI仅获对应Topic/组消费权限。半消息不可消费；生产者确认本地事务后COMMIT使消息可见，ROLLBACK则不交付。Python仍以SimpleConsumer消费已提交消息，受理短事务完成后ACK，不运行长解析。凭据、私网白名单及生产范围独立校验。

### 8.2 本地事务、回查与恢复

不建立outbox发送表或定时扫描发送器。knowledge的kb_index_job保存索引尝试、请求回执及事务业务事实，既供管理查询，也供TransactionChecker判断，不是待发送队列表。

1. add包含clientRequestId和文档版本。先按requestedBy+clientRequestId查回执，同义返回原jobId/状态，异义冲突；重复PREPARING请求只查进展，不再并行发送。新尝试锁文档及前次任务，登记固定jobId/原请求及不可变输入、submitState=PREPARING和30秒准备截止，并设置currentJobId、递增文档版本。该准备记录不是已受理成功。query用jobId或当前发起人的原clientRequestId二选一查询，均重新授权。
2. 在数据库事务外发送半消息，取得明确半消息回执后，再短事务锁文档→本地任务；确认仍DRAFT、当前任务及准备事务提交后的文档版本匹配、状态PREPARING且未过截止，写submitState=COMMITTED、提交时间和INDEX_REQUESTED事件。并发修改导致确认失败时，先以相同锁序提交ABORTED再ROLLBACK，不把失败认定扩大为已提交事务的回滚。
3. 本地事务提交后向Broker COMMIT。此时HTTP可202返回“本地已提交、等待AI受理”；Broker二次确认失败也不能撤销已提交业务，交由事务回查。半消息发送失败/未知且本地尚未提交时，不执行确认事务，结束为ABORTED或等待期限收敛，返回明确失败/未知及原键查询入口，不能报告任务已受理。

取消仅用于本地SUBMIT已COMMITTED且仍DRAFT的尝试，入参jobId及rowVersion：先返回既有COMMITTED/PREPARING取消回执，新操作再比较版本。锁文档→任务，登记cancelState=PREPARING、cancelOperationId及30秒截止并递增文档版本；半消息明确接收后短事务按准备后的版本重核条件，将取消COMMITTED并写INDEX_CANCEL_REQUESTED，再向Broker COMMIT。取消准备中禁止发布/换尝试；取消ABORTED须读取最新版本后显式再试并分配新cancelOperationId，旧请求不能自动开启新取消操作；已COMMITTED沿原操作幂等，不回退。SUBMIT准备中先等待其COMMITTED或ABORTED，不能跳过未知结果新建/取消远端任务。

TransactionChecker按jobId/requestHash/command/operationId查询业务库：对应本地COMMITTED→COMMIT，明确ABORTED或已被替换的旧取消操作→ROLLBACK；PREPARING未过截止、数据库不可达或锁超时→UNKNOWN。过期PREPARING必须先以同一文档→任务锁序条件改ABORTED，提交后才ROLLBACK，晚恢复的原请求无法再提交。事务处理中不能仅凭一次查询无记录直接ROLLBACK；预登记应早于半消息，合法信封查不到对应记录是异常，先UNKNOWN并告警核对。已提交SUBMIT即使后来取消、换尝试或完成，回查仍COMMIT，不能按当前文档状态回滚历史事实。

AI相同jobId/requestHash幂等受理，lastCommand只SUBMIT→CANCEL。取消先到保存完整CANCELLED墓碑，迟到SUBMIT不复活；已终态取消保留执行结果并记lastCommand=CANCEL。不同输入/非法信封不ACK为成功，经过有界重投进入死信。operationId用于事务证明与诊断，不能绕过同jobId防重。

页面分别显示Java提交/取消状态、AI受理情况和执行状态；AI受理须GetStatus核对requestHash及lastCommand，未见NOT_FOUND或查询失败不证明消息不存在。只有本地SUBMIT提交、无准备中/已提交取消、AI成功且解析收敛及双索引完整才能发布。新尝试须前次本地ABORTED，或已提交前次AI终态且解析收敛；前次未知时不换jobId。

消费初始invisibleDuration30秒、受理事务5秒、maxDeliveryAttempts16（含首次），ACK丢失依靠原身份重投收敛。事务回查及消息保留均有预算，不能承诺Broker永久保留或无限恢复。knowledge停机须在回查窗口内恢复；回查耗尽、Broker数据丢失、消息过期或死信处置，先核对持久业务事实和AI任务，再由授权管理员replay-command重放已COMMITTED的原指令。动作先落INDEX_REQUEUED审计事件，表示管理员发起重放，不能作为Broker接收或AI受理证明；发送失败/未知如实返回。该动作同样发送事务消息，由已有提交事实确认，不改任务/片段，不生成新jobId；已提交取消优先重放CANCEL，绝不能重放SUBMIT来撤销取消。不自动扫描业务表重发，超预算须显式处置。

### 8.3 上传互斥

knowledge在已授权上传请求内使用Redisson按createdBy+clientUploadId互斥，文件校验后、有副作用的OSS写入前取锁，取锁后重查回执和当前权限。锁忙返回409及稳定UPLOAD_IN_PROGRESS错误码，附Retry-After；Redis依赖失败503。两者都保留原键供查询/重试。上传同义重放返回原修订，异义409；锁、数据库或HTTP超时均不能证明OSS未写入，最终唯一回执和孤立对象对账见数据库设计。

草稿正式回执提供两个不同授权入口：ReadDraftReceipt使用原ActorRef，核对本人及当前工单访问权限；ReconcileDraftReceipt只允许经mTLS及AI服务凭据认证的维护器，输入ownerId/draftRootId，仅返回精确原拥有者已提交的最小回执或空结果，不返回正文、不模拟会话、不提供写入能力。无回执只代表当前查询未看到已提交结果，不能证明没有在途事务。维护器处理仍遵守根唯一采用、30秒证明窗口、会话→任务锁序及系统事件；迟到结果可继续收敛。

taskStateVersion、diagnosisContextVersion、ticketRowVersion和ticketEventSequence互不代替。新运行受理先查原键，再核版本、队列及预算；问题回复先保存，排队失败保留inputMessageId，沿原Run请求键查询/重试。活跃运行拒绝事实更正/回复，用户可以先取消再提交。过期/被撤回/环境过时问题不能自动复活，返回409；同一已回答问题同义返回原回执，异义走明确更正。

DiagnosticCheck兼容CLARIFICATION与CHECK，每实例只接收一次明确反馈。人工ANSWERED表示收到反馈，不等于执行或恢复；规范answer按answerSchema验证；CHECK还必含executionStatus=NOT_PERFORMED/PERFORMED和outcome=UNKNOWN/UNCHANGED/IMPROVED/RESTORED_REPORTED，未执行只允许UNKNOWN；CLARIFICATION仅value，工具观测才可OBSERVED_DONE。重复检查新建实例，旧环境项为NEEDS_RECHECK；人工答复以请求中的checkId定位，复查使用新实例身份。任务hypotheses最多8项，以hypothesisKey和支持/反证factIds返回，历史由events分页读取，不提供独立假设CRUD。

内部只读工具search_knowledge支持可空documentTitle（完整标题，最多300字符），只过滤当前已授权集合；无匹配返回空候选且不产生查询Embedding。read_evidence仅接受正文回执的续页定位，endOffset不构成nextOffset；正文回执明确contentScope=SECTION，章节完整不等于整篇完整。排障自由正文、假设、草稿和自由澄清经无工具依据核验后才进入提交；审核检查原指令与宿主状态说明单独执行合同及事务校验，核验结果不直接作为浏览器协议。最多一次纠正；重复无效或核验预算不足返回成功持久化的INSUFFICIENT_EVIDENCE及宿主说明，checks/草稿为空，不返回被拒绝候选。该终态表示安全收束，不代表任务已解决；普通咨询维持原输出错误合同。

连续三次取证无新增依据只关闭工具，使用既有有效证据进入统一最终阶段；没有诊断依据则由宿主提交证据不足说明，不追加模型生成。不得直接将已有合法检查改为转人工；后续仍复核执行权、来源授权、检查前提和原Run/任务预算，经原依据核验与最终事务提交，不重置预算或再次取证。

取证阶段模型提出白名单外工具时，整批提议不执行，调用仍记FAILED/INVALID_MODEL_RESULT。仅在供应商响应已确认完整用量且诊断Run尚处取证阶段时，宿主关闭取证能力，按此前有效证据进入无工具最终阶段；没有充分证据则直接给出证据不足结果。不得再次尝试原工具、继承非法回应正文或假装取得新来源。后续候选及核验继续消耗原Run/任务预算；最终阶段协议失败、未知计量、授权、环境、租约及依赖失败仍终止，不走此收束路径。

审核规程的宿主状态与可选模型分析分别验收。模型假设、记录/解决草稿及转交对象作为一组核验；仅这组内容被语义拒绝或其核验预算不足时，整组不交付，保留原审核检查或宿主结论进入最终事务校验，不据此更改既有假设。原候选和已发生的核验保留调用账目。自由澄清及普通回答仍整份纠正或拒绝；协议、身份、来源、环境和依赖失败不能走此路径。检查前置条件及当前最新恢复反馈仍在提交锁内复核，舍弃可选内容不等于检查已通过或已执行。

结果citations为{number,sourceUsageId,title,locator,excerpt,documentId}的有界列表（documentId仅知识来源非空），来自Run已校验引用映射与本轮source_usage；摘要不暴露内部提示词。number对应本轮实际source_number，仅在runId内有效；sourceUsageId与runId共同绑定原件授权读取。title与定位来自后端核验来源，不能使用模型提供的任意URL。读取回答/消息/草稿时核验全部实际来源，包括摘要传递依赖，不只检查显示的citations。Run快照返回executionPhase/iterationNumber与安全恢复说明，不承诺可从任意节点恢复。

运行成功只表示这一轮完成。answerType=ANSWERED/CLARIFICATION/INSUFFICIENT_EVIDENCE/HANDOVER；提出待答后Run=SUCCEEDED、task=WAITING_USER。环境变化用FAILED及诊断CONTEXT_CHANGED，失效租约为INTERRUPTED；这些不是另造Result数字码。读取旧结果先检查权限，普通过时返回stale=true及版本，风险撤回/撤权隐藏受影响正文并返回safeReason，依赖失败明确503。

模型供应商拒绝、限流、认证或传输故障使已受理Run结束为FAILED/MODEL_PROVIDER_UNAVAILABLE；查询原Run仍是成功读取持久状态，不转换成新的Result数字码。调用账目对明确4xx拒绝（408除外）记FAILED/PROVIDER_REJECTED，只保存受控provider_error原因；408、连接或服务端故障保持UNKNOWN/PROVIDER_RESULT_UNKNOWN，不能从超时推断未执行。未取得计量仍为null，业务及评测均不自动重发未知付费请求。

内部RPC的依赖不可用、协议错误或超时使已受理Run结束为FAILED/DEPENDENCY_UNAVAILABLE，不能归为模型输出错误或用户登录失效；用户会话撤销等可信业务拒绝保持其独立含义。前端说明依赖故障并保留原反馈，评测遇该诊断停止后续实例。诊断码不是HTTP响应数字码，查询原Run继续返回其持久状态。内部gRPC及Zipkin明确直连已配置端点，不继承操作系统HTTP代理；连接与调用预算、双向TLS和服务认证保持有效。

草稿返回draftId、draftRootId、revisionNumber、contentSha256、content、expiresAt、用途及版本。用户编辑先建立新修订，再确认该修订；修订提交携带clientRequestId、原contentSha256及类型化content，保留原根及期限，响应未知按原请求键查询，不覆盖原修订；正式ticket动作携带sourceDraftId/sourceDraftRootId/contentSha256和自己的动作键，最终字段须与被确认修订相同。草稿撤回前已经通过校验的在途请求仍可能完成；ValidateDraft返回短时校验证明（validationId、validatedAt、validUntil、draftRootId、contentSha256，最多30秒），仅在内部RPC响应传递，不作为浏览器授权令牌；ticket校验该返回属于本次调用并在提交前重核本地状态。CREATE_TICKET允许已确认事实模板且sourceRunId为空；BOOK_ONSITE限客户任务已核实handoverTicketId，其他处理用途限技术会话当前处理人；均需目标工单和明确依据，不额外付费生成。ticket按原receipt优先对账，新动作再校验，草稿根跨用途/修订只采用一次。Java事务已提交后AI不可用不撤销业务；查询回执不依赖重新ValidateDraft。草稿撤回和在途采用发生竞争时以Java回执为准，不能声称跨库原子取消。

所有正式动作均可不带草稿通过人工表单执行；人工链不依赖AI。反馈不提供会话共享开关，知识复用采用人工确认脱敏材料及已有Markdown资料发布流程，不新增候选提交/审核接口。

| 路径 | 方法 | 合同 |

| /tickets/{id}/attachments | POST | multipart metadata={clientUploadId,contentFormat,visibility}及file，TEXT/LOG/JSON UTF-8≤1MiB；返回附件ID及真实阶段 |

Agent通过list_diagnostic_attachments发现候选；参数仅可空afterId，返回attachmentId、文件名、contentFormat、十进制字符串redactionVersion、sha256及下一页游标。发现不登记正文引用。inspect_diagnostic_text参数为attachmentId、redactionVersion和从0开始的Unicode字符offset；工单及ActorRef由宿主固定，每次重核精确版本，按最多4000字符返回原样摘录及nextOffset，最后一页nextOffset为空。定位记录起止字符及脱敏版本，非首尾完整读取不能标为整个附件。工具不执行正文、打开链接或读取原件。实际摘录登记ATTACHMENT来源，历史回答、草稿和跨轮事实依赖都重新读取核验当前授权及摘要，不能凭已存摘录绕过换版、删除或撤权。

客户仅可上传和读取本人有权工单的PUBLIC附件；服务团队按当前客户范围读取PUBLIC/INTERNAL。只有原上传者可确认脱敏文本及AI授权；原上传者、范围内客服或当前有权处理技术人员可撤销附件访问。附件行版本与脱敏版本独立，确认/删除回执的resultSnapshot固定attachmentId、attachmentStatus、attachmentRowVersion、redactionVersion及aiUseAllowed，不用当前附件快照替代原提交结果。下载使用no-store及强制附件响应，不提供签名URL或浏览器内执行。查询未知上传只按已登记Key核验精确版本及摘要，404不授权自动重传。


## 10. SSE、超时与后台协议

普通 JSON 先创建运行，再以 POST fetch 订阅既有 runId，响应 text/event-stream。每个业务事件包含 runId、sequence 和类型化 JSON，sequence 在单次连接内递增，不承诺永久事件日志或跨连接增量重放；断线读取持久快照。

| 事件 | 含义 |
| --- | --- |
| stage | `status`、`executionPhase`、`iterationNumber`；任一字段变化时更新，同一运行可以在 RUNNING 状态下多次更新 |
| task | 成功运行提交的 `taskId`、`status`、`taskStateVersion` 和 `pendingCheckIds`；用于定位本轮新增待答项。咨询没有任务，来源隐藏时省略此事件 |
| answer | 已校验并提交的完整正文及 answerType |
| citations | 当前有权真实来源及PDF页码、Markdown锚点/行区间或事件定位 |
| tool | 已持久且有权的工具名称、状态及安全摘要，不输出隐藏思维链 |
| done | 已持久确认的终态 `status` 与来源隐藏标记 `sourcesHidden` |
| error | 安全协议/依赖错误及查询原运行的指引 |

正文及引用在固定证据、校验、终态提交和交付授权后发送，不输出未校验 Token。心跳用 SSE 注释。客户端正确处理 UTF-8 分段、多行 data 和跨块，读完不等于成功。事件缓存、订阅、TTL 有界，慢订阅者退出后查询快照。

断开订阅只关闭本地读取，不取消运行；主动取消先提交终态再尽力停止上游。身份变化结束交付，迟到模型输出不能覆盖取消或失去执行权的状态。代理关闭缓冲，读超时覆盖订阅预算。

内部HTTP设置连接、读取和总预算，允许有限退避，副作用重试沿原身份。XXL-JOB通过独立执行器协议及accessToken触发预定义BEAN，只调用所属Service的有界扫描，任务不携带浏览器Cookie或任意SQL/脚本。调度恢复按数据库事实补扫，触发成功不等于业务完成。Sentinel流控429、依赖熔断503与业务权限错误分开；公开入口在追踪提取前清理外来traceparent/tracestate/baggage及B3头，内部可信HTTP、gRPC metadata和MQ按系统设计传播W3C上下文。

## 11. gRPC与Protobuf合同

### 11.1 类型及兼容性

.proto唯一源位于desk-api/src/main/proto/desk_contracts/{common,user,ticket,knowledge,ai}/v1，package为servicedesk.{owner}.v1，Java包为com.yangaobo.servicedesk.api.{owner}.v1并启用java_multiple_files。common仅稳定的ActorRef和RpcErrorDetail等协议基础类型，业务枚举由所有者维护。Java与Python生成物各有独立包名，不跨语言共享JAR。

使用proto3；字段lower_snake_case，ID/SHA字符串仍按业务格式校验，version/total用非负int64且不超Java Long上限，时刻用google.protobuf.Timestamp；浏览器JSON继续十进制长整数字符串和ISO8601。需要区分缺失/零值时使用optional，枚举0为UNSPECIFIED且写入拒绝；未来局部更新明确optional/FieldMask含义。Protobuf不替代业务校验，不使用万能Any/Struct承载业务全集。

新增字段使用新编号，删除字段及名称reserved；不得复用编号、改变既有类型/含义或随意移动包/方法。破坏性变化另开v2并明确消费者迁移窗口。生成物不手改、不按手写class/Serializable/中文Javadoc规则补样板，中文合同和字段说明写在.proto；不持久化生成类型或直接返回为前端VO。构建生成Java message/stub及Python_pb2/_pb2_grpc/_pb2.pyi，验证导入及跨语言互通；编译可过不代表线合同兼容。

### 11.2 认证、错误及运行边界

生产RPC启用TLS、校验CA和服务端名称，开发使用独立开发CA；每调用方独立凭据放authorization metadata，服务端拦截器从有效凭据识别服务、限制允许方法，再执行用户/资源授权。身份头、trace或ActorRef不提供服务认证。凭据不进.proto、日志或浏览器；反射在生产关闭，标准grpc.health.v1.Health/Check仅受控私网调用。Gateway不做gRPC-Web或自动JSON转码。

成功直接返回类型化响应，不套Result。失败使用gRPC Status和google.rpc.Status details，内含共同RpcErrorDetail(code、安全message、trace_id、可选retry_after_ms)，复用错误码所有权。UNAUTHENTICATED/PERMISSION_DENIED/NOT_FOUND映射401/403/404，INVALID_ARGUMENT映射400或422，ALREADY_EXISTS/ABORTED/FAILED_PRECONDITION映射409，DEADLINE_EXCEEDED映射504，UNAVAILABLE映射503，INTERNAL映射500；RESOURCE_EXHAUSTED按稳定业务码区分429流控和503资源忙。服务凭据/TLS失败是依赖故障，不能误报用户登录失效；仅可信详情明确会话失效才触发前端401。无响应、取消、正常空集合和不存在分别处理。

身份客户端单次传输使用2.9秒预算，为3秒用例保留交付余量；Java及Python领域调用均从方法上限与父剩余预算较小值扣除100毫秒，剩余不足时不发起调用，原件流单次最多119.9秒；服务端容许grpc-timeout有效数字编码的10毫秒舍入误差。user身份RPC以CA/服务端证书/服务端私钥启用双向TLS，AI同时提供客户端证书和独立服务令牌；读取浏览器请求刷新会话活动时间，后台ActorRef重核不延长会话。

每次RPC显式Deadline：身份3秒、支持上下文/工单事件/来源/草稿5秒、索引状态15秒、原件流120秒，均受父用例剩余预算限制；通道建立/重连预算2秒。关闭无限wait-for-ready，默认关闭业务自动重试，幂等只读需要时最多一次退避且共用Deadline；重试不能生成新身份或自动重跑付费任务。Channel/stub按进程及目标复用，关闭时有界排空；Java阻塞stub不在WebFlux事件循环调用，Python使用grpc.aio且资源归所属事件循环。

Unary消息上限4MiB，有界集合不得静默截断。ReadOriginal与ReadRedacted为业务server-stream：首帧固定版本元信息、contentFormat及大小/SHA，后续每块最多64KiB，含连续字节offset；ReadOriginal总量最多20MiB，ReadRedacted最多1MiB，按就绪/流控发送。调用方写有界临时文件，检查顺序、总量、最终RPC成功与SHA后才交解析；超时/断流删除未校验临时结果，重试从头读取同一版本，不以EOF或部分内容当成功，不将文件塞进单个Protobuf消息。

Java gRPC边界以显式拦截器落实认证、Deadline、错误转换、Sentinel及W3C追踪，异步资源到完成/取消才退出；Python aio边界执行同等认证/预算和追踪。UNAVAILABLE/DEADLINE_EXCEEDED/INTERNAL等技术故障纳入依赖熔断统计，权限、输入、业务冲突及正常取消不计；Trace沿metadata传播，不向模型或其他云服务泄漏服务凭据。
