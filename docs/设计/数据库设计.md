# 数据库设计

本文定义完整关系数据合同。字段和表按业务所有权、独立生命周期、查询与并发需要组织。业务机制见[系统设计](系统设计.md)，线协议见[接口约定](接口约定.md)。当前迁移版本、已核对的结构和历史 SQL 快照的适用范围见[数据库初始化与迁移](../sql/README.md)。

## 1. 环境、所有权与通用约束

关系存储采用 MySQL 8.4 LTS / InnoDB；向量独立存放 Qdrant，关键词副本存放 Elasticsearch。开发与业务测试使用 test，生产使用 prod，自动化测试使用独立可销毁实例中的 ci。每个服务、每个环境使用独立数据库。当前开发的四个 test 库统一通过 root 连接，用户名和密码由各服务本机配置提供；数据所有权及禁止跨库访问的服务边界不变。生产及自动化测试使用独立运行账号和迁移账号，可以共用实例，但不能共用业务账号。

| 服务 | MySQL 数据库 | 生产及隔离测试运行账号 | 结构维护 |
| --- | --- | --- | --- |
| desk-user | desk_user_{env} | desk_user_app_{env} | 所属 Flyway 历史与迁移 |
| desk-ticket | desk_ticket_{env} | desk_ticket_app_{env} | 所属 Flyway 历史与迁移 |
| desk-knowledge | desk_knowledge_{env} | desk_knowledge_app_{env} | 所属 Flyway 历史与迁移 |
| desk-ai | desk_ai_{env} | desk_ai_app_{env} | API启动执行Alembic，命令行共用迁移链 |

{env} 为 test、prod 或 ci；迁移账号按 desk_{service}_migrate_{env} 命名。MySQL 的 schema 与 database 同义，每个环境明确建库，不以同库命名空间代替独立数据库。本文逐表标题中的 desk_user、desk_ticket、desk_knowledge、desk_ai 表示逻辑所有者，实际连接库带环境后缀，业务 SQL 不写死环境库名。生产及隔离测试的运行账号仅获所属库所需的表级权限，审计表限制为读取和插入；无 DDL、跨库、全局管理权限，迁移账号独立执行 DDL。开发环境通过IDEA root数据源创建空库，应用使用同一root账号启动迁移；已有手工表需先比对并显式登记初始历史。生产不加载开发本机配置，迁移使用独立DDL凭据。Qdrant collection 与 ES 知识索引也按环境隔离，由 desk-ai 维护；其他业务服务不直接访问。ES中的业务数据仅为知识关键词副本，运行日志经ELK另存独立数据流，Zipkin采用有界内存存储，均不进入业务ER。

服务内关联用外键，由所属迁移维护。跨服务关联保存稳定 ID，通过可信接口校验，不在同实例上跨服务库联表或建立外键。工单和设备的客户一致性在 ticket 内由复合外键保护，客户组织存在性和角色范围通过 user 核验。

表名、字段名不存在唯一行业词典；本项目选择有业务含义的小写下划线、单数表名、职责前缀及明确单位/时间后缀，避免缩写拼盘、保留字和同义异名。starts_on/ends_on表示含首尾的日期，first_accepted_at表示第一次接单/分派，不能当作第一次向客户回复；changed_by类操作者与owner/requester/assignee分清。表前缀和32位UUID属于本项目约定，不声称是SQL强制标准。

表名用单数英文 lower_snake_case，按业务使用 sys_（身份）、it_（支持范围、型号与设备）、sd_（工单）、kb_（知识发布）、ai_（解析与排障）。字段同样使用 lower_snake_case。主键统一 id，引用以资源名加 _id 命名，created_by、granted_by 等审计字段表示操作者账号 ID。customer_id 统一表示客户组织，owner_id 表示会话及派生数据的拥有账号。status 表示本表生命周期，publication_status 表示发布态，row_version 用于乐观并发。时刻用 _at 和 datetime(6)，统一保存 UTC；日期用 _on 和 date，服务截止日按 Asia/Shanghai 判断。所有连接 time_zone 固定 +00:00，默认时间使用 CURRENT_TIMESTAMP(6)。Java Instant 与 Python 有时区 datetime 在持久化边界显式转换成 UTC，读取后恢复 UTC 语义，HTTP 仍输出含时区的 ISO8601。datetime(6) 本身不保存时区，不能把本地墙上时间直接写入。毫秒和字节分别用 _ms、_bytes。资源 ID 由所属服务生成，跨服务提交的任务 ID 由发起服务先生成，纯关联表可用复合主键；具有独立维护生命周期的Java主实体使用单列id加业务UNIQUE，关联表由所属完整用例Mapper操作，不调用不支持复合主键的通用CRUD。该选择依据[MyBatis-Plus官方常见问题](https://baomidou.com/en/reference/question/)。

业务 ID 统一使用 `varchar(32)`，由标准 UUID 去掉四个连字符生成 32 位小写十六进制字符串。Java 使用 `String`，Python 使用 `str`。主键和客户端幂等键使用 `CHECK` 校验 `^[0-9a-f]{32}$`。外键、逻辑引用和复合引用与目标列的类型、长度及格式一致。客户端生成请求或动作幂等键并在重试时复用，唯一范围由各表定义。工单编号沿用独立展示编号。

同一业务ID贯通Java内部HTTP、跨语言Protobuf、MQ信封、JSON快照、ES片段文档键和持久化列。框架会话引用`session_ref`与worker领取令牌`claim_token`使用`varchar(36)`保存规范的小写带连字符UUID，并作格式检查。HTTP/Protobuf的sessionRef均为带连字符UUID字符串。MinerU的任务和文件标识按上游协议保存。原件通过持久化storage_bucket、storage_key和storage_version_id定位OSS对象版本；OSS Version ID是供应商标识，不套用业务ID格式。

结构由各服务所属迁移显式维护，首个DDL使用统一标识及字段合同。标识演进需同步外键、复合键、JSON快照、幂等键、消息与检索键，在隔离库核对历史引用和授权后交付，原件定位不随标识格式任意迁移。

表和字段写中文数据库注释；表使用 utf8mb4 / utf8mb4_0900_bin，保持大小写及尾部空格的精确比较；ID、状态、代码、摘要和对象定位列及其引用列使用一致排序规则。展示文本的模糊检索显式定义比较方式。业务 ID 用 `CHECK (REGEXP_LIKE(id, '^[0-9a-f]{32}$', 'c'))` 限定小写，不因默认不区分大小写而接收大写。SHA-256 为 varchar(64)，同样检查 64 位小写十六进制。

必填字段显式 NOT NULL，必填文本限制非空白，状态由 CHECK 和枚举共同约束。boolean 是 MySQL TINYINT(1) 的别名，增加 IN (0,1) CHECK；整数范围、时间顺序和空值组合均有约束。CHECK不能跨表核验角色、资料格式归属或前驱顺序；这类规则由本地事务/用例验证，FK只保护已声明键关系。CHECK接受UNKNOWN，涉及可空列必须显式写 IS NULL / IS NOT NULL，不能依赖比较自行拒绝空值。TEXT 最多 65535 字节，接口、模型输出和切片均设字符与 UTF-8 字节预算；大于该界限的实际消费者出现时显式迁移 MEDIUMTEXT，不依赖静默截断。启用严格 SQL 模式，禁止零日期。updated_at 由业务更新显式维护，不使用 ON UPDATE 隐式改变审计；row_version 非负且比较后递增。

快照使用 MySQL JSON，不保存向量列。快照要求 JSON_TYPE 为 OBJECT、schema_version 存在且为正整数；集合放具名字段。ai_chunk.error_codes 单独为 JSON 字符串数组，数据库验证 ARRAY、用例验证每项格式、去重及预算，写入时显式提供 []。定位快照统一为带schema_version的对象，kind区分PDF、MARKDOWN、TICKET_EVENT、DIAGNOSTIC_FACT、ATTACHMENT、MESSAGE、PROCEDURE_CHECK；PDF为pages，文本为segments（锚点及行区间），事件/事实按稳定ID及序号定位。非PDF来源不伪造页码。JSON 不直接建立普通 B-tree 索引，需要查询的标量由稳定业务列承载；检索数组与部分唯一语义采用本项目明确设计的字段及约束，不照搬其他数据库语法。生成列仅用于当前明确的唯一约束，见各表及文末并发规则。

约束按 pk_/uk_/fk_/ck_/idx_ 命名，遵守 MySQL 表、列和索引 64 字符上限。CHECK 名称在服务库内唯一，包含表名。外键默认 NO ACTION（InnoDB 立即检查，不支持延迟外键）；复合 FK 指向同顺序、完整的 UNIQUE 列组，不依赖非唯一父键。循环引用按先建表、再 ALTER ADD CONSTRAINT 安装，不用禁用外键检查掩盖迁移次序。已有唯一索引可满足查询时不重复建索引。Pydantic 和 Java 校验与数据库约束分别覆盖各自边界。

三份Flyway历史、Alembic版本及Spring Session JDBC的会话和属性表属于技术数据，不纳入业务表统计。XXL-JOB使用独立xxl_job_{env}技术库、独立账号和同版官方SQL（8张技术表），不套用业务ID和业务表规范；业务服务运行账号不能读写该库，Admin管理触发及执行记录，业务进度仍在所属库。会话表使用框架MySQL方言，由user迁移安装；JDBC Session供身份服务实例共享，账号、角色与授权以user当前事实为准。内部核验使用会话行PRIMARY_ID作为非凭证引用，user核验过期、账号与auth_version；用于Cookie的SESSION_ID仅在user边界内解析。 [Spring Session JDBC表结构](https://docs.spring.io/spring-session/reference/3.5/configuration/jdbc.html)

| 逻辑库 | 目标自有表数 | 职责 |
| --- | --- | --- |
| desk_ai | 15 | 解析副本、会话/任务/运行、事实/检查、来源和调用账目 |
| desk_knowledge | 5 | 修订、事务索引、修订内规程与人工编写知识 |
| desk_ticket | 12 | 服务资格、人工履约、全局动作回执与附件 |
| desk_user | 5 | 身份与范围 |

共37张自有表；Spring Session、Flyway/Alembic及XXL技术表另计。服务内FK与跨服务逻辑引用分开，所有新增结构等待迁移实现。

## 2. `desk_user.sys_organization` 客户与服务商组织

| 字段 | 类型 | 空值/默认 | 含义与约束 |
| --- | --- | --- | --- |
| `id` | varchar(32) | 必填，无默认 | 主键，由所属后端生成 |
| `organization_code` | varchar(64) | 必填，无默认 | 规范化小写后全局唯一，停用不复用 |
| `organization_name` | varchar(100) | 必填，无默认 | 展示名称，不作为授权标识 |
| `organization_type` | varchar(32) | 必填，无默认 | CUSTOMER / SERVICE_PROVIDER |
| `service_provider_guard` | tinyint | 可空，STORED 生成 | SERVICE_PROVIDER 为1，否则 NULL；唯一 |
| `status` | varchar(32) | 必填，ACTIVE | ACTIVE / DISABLED |
| `created_at` | datetime(6) | 必填，CURRENT_TIMESTAMP(6) | 记录创建时间 |
| `updated_at` | datetime(6) | 必填，CURRENT_TIMESTAMP(6) | 更新时显式维护，默认值不自动随 UPDATE 改变 |
| `row_version` | bigint | 必填，0 | 非负，更新比较旧值后加一 |

organization_code 唯一且非空白，organization_type/status 使用 CHECK。service_provider_guard 的 UNIQUE 限制 SERVICE_PROVIDER 最多一条，服务商由身份初始化流程建立。

停用组织不删除账号、设备和工单。每次身份核验检查组织状态，客户停用后停止新的客户业务；已有工单仍可由具有当前客户范围的有效服务人员处理。禁止停用唯一服务商导致全部管理员失效，纳入最后管理员保护事务。索引按状态和稳定 ID 支持有界组织选择。

## 3. `desk_user.sys_user` 账号

| 字段 | 类型 | 空值/默认 | 含义与约束 |
| --- | --- | --- | --- |
| `id` | varchar(32) | 必填，无默认 | 主键，由所属后端生成 |
| `organization_id` | varchar(32) | 必填，无默认 | 本库 FK → sys_organization |
| `username` | varchar(64) | 必填，无默认 | 去首尾空格、转小写，全局唯一 |
| `password_hash` | varchar(255) | 必填，无默认 | Spring Security 哈希及算法标识，不能输出 |
| `display_name` | varchar(100) | 必填，无默认 | 姓名，不作授权条件 |
| `status` | varchar(32) | 必填，ACTIVE | ACTIVE / DISABLED |
| `must_change_password` | boolean | 必填，true | 初始化和重置后强制改密 |
| `password_changed_at` | datetime(6) | 可空 | 首次主动改密前为空 |
| `last_login_at` | datetime(6) | 可空 | 仅认证成功更新 |
| `auth_version` | bigint | 必填，0 | 改密、角色、组织、客户范围或停用等认证相关变更加一 |
| `created_by` | varchar(32) | 可空 | 本库 FK → sys_user，首次管理员初始化可空 |
| `created_at` | datetime(6) | 必填，CURRENT_TIMESTAMP(6) | 记录创建时间 |
| `updated_at` | datetime(6) | 必填，CURRENT_TIMESTAMP(6) | 更新时显式维护，默认值不自动随 UPDATE 改变 |
| `row_version` | bigint | 必填，0 | 非负，更新比较旧值后加一 |

username 全局唯一，数据库以 CHECK 限制小写 ASCII 字母、数字、点、下划线及连字符，首字符为字母或数字，长度3至64。auth_version、row_version 非负，停用账号保留用户名。organization_id 和 created_by 为本地外键，账号保留历史。管理列表使用 (organization_id,status,id)。

组织类型与角色组合由 Service 在同一管理事务验证。组织调动只修改当前账号归属，不迁移旧业务记录的客户或拥有者；客户历史读取同时匹配当前组织和原 owner/requester。失去处理权限的技术人员由范围内客服转派，不删除原时间线。改密、重置、停用、角色/组织/服务范围变更增加 auth_version；会话只保存 ID 和版本，在线核验读取当前事实。最后有效管理员保护先锁唯一服务商组织行，再读取并锁定受影响账号和角色，所有组织停用、管理员降权及账号停用入口遵循同一锁顺序。在锁内核对至少一名有效管理员，不只做一次 COUNT 再分别更新。

## 4. `desk_user.sys_user_role` 账号角色

| 字段 | 类型 | 空值/默认 | 含义与约束 |
| --- | --- | --- | --- |
| `user_id` | varchar(32) | 必填，无默认 | 联合 PK，本地 FK → sys_user |
| `role_code` | varchar(32) | 必填，无默认 | 联合 PK，五种固定角色码 |
| `granted_by` | varchar(32) | 可空 | 本地 FK → sys_user，首次初始化可空 |
| `created_at` | datetime(6) | 必填，CURRENT_TIMESTAMP(6) | 记录创建时间 |

联合主键 (user_id, role_code)，按 (role_code, user_id) 支持最后管理员保护和角色查询。role_code CHECK 限定 CUSTOMER_USER、SERVICE_AGENT、TECHNICIAN、KNOWLEDGE_ADMIN、SYSTEM_ADMIN，显示名由应用角色定义提供。角色增删与用户 auth_version 同事务，客户与服务商角色不得混合。

撤销最后一个SERVICE_AGENT/TECHNICIAN角色时同时清理该用户全部 sys_user_customer_scope；仍保留另一服务角色时范围保留。删除角色关联是显式撤权，不能级联删除账号。

## 5. `desk_user.sys_user_customer_scope` 服务人员客户范围

| 字段 | 类型 | 空值/默认 | 含义与约束 |
| --- | --- | --- | --- |
| `user_id` | varchar(32) | 必填，无默认 | 联合 PK，本地 FK → sys_user |
| `customer_id` | varchar(32) | 必填，无默认 | 联合 PK，本地 FK → CUSTOMER 类型的 sys_organization |
| `granted_by` | varchar(32) | 必填，无默认 | 本地 FK → sys_user，授权管理员 |
| `created_at` | datetime(6) | 必填，CURRENT_TIMESTAMP(6) | 记录创建时间 |

联合主键(user_id, customer_id)，反向索引(customer_id, user_id)。Service 校验用户属于服务商、有 SERVICE_AGENT 或 TECHNICIAN 角色，customer_id 必须为客户组织。范围不是全平台租户管理员权限。

授予、撤销在同事务增加用户 auth_version 并追加管理事件。撤销后按当前权限拒绝访问，客服按当前范围重新指派工单。

## 6. `desk_user.sys_admin_event` 身份管理审计

| 字段 | 类型 | 空值/默认 | 含义与约束 |
| --- | --- | --- | --- |
| `id` | varchar(32) | 必填，无默认 | 主键 |
| `actor_type` | varchar(16) | 必填，无默认 | USER / BOOTSTRAP |
| `actor_user_id` | varchar(32) | 可空 | 本地 FK → sys_user，USER 必填，BOOTSTRAP 为空 |
| `target_user_id` | varchar(32) | 可空 | 本地 FK → sys_user |
| `target_organization_id` | varchar(32) | 可空 | 本地 FK → sys_organization，与目标账号恰有一个 |
| `event_type` | varchar(32) | 必填，无默认 | ORGANIZATION_CREATED / ORGANIZATION_UPDATED / ACCOUNT_CREATED / ACCOUNT_UPDATED / ACCOUNT_ENABLED / ACCOUNT_DISABLED / PASSWORD_RESET / ROLES_CHANGED / CUSTOMER_SCOPE_CHANGED |

管理变更、相关授权关联、auth_version 及对应审计事件同事务提交。角色和范围变化记录有序变更项，账号或组织变化记录实际受影响字段。初始化可用 BOOTSTRAP，日常写入必须对应当前操作者。仅系统管理员查询，运行账号仅插入和读取。分别建立 (target_user_id,created_at DESC,id) 和 (target_organization_id,created_at DESC,id) 复合索引，查询显式限定非空目标。

## 7. `desk_ticket.it_service_item` 支持服务项目

| 字段 | 类型 | 空值/默认 | 含义与约束 |
| --- | --- | --- | --- |
| `id` | varchar(32) | 必填，无默认 | 主键 |
| `service_code` | varchar(64) | 必填，无默认 | 规范化大写ASCII稳定代码，全局唯一且停用不复用 |
| `category` | varchar(32) | 必填，无默认 | TERMINAL / PRINTING / NETWORK / OFFICE_SOFTWARE |
| `service_name` | varchar(100) | 必填，无默认 | 客户可理解的项目名称 |
| `support_scope` | text | 必填，无默认 | 明确支持产品、环境、版本及排除条件，最多5000字符 |
| `onsite_supported` | boolean | 必填，false | 项目是否允许人工开放现场服务 |
| `status` | varchar(16) | 必填，ACTIVE | ACTIVE / DISABLED |
| `created_by` | varchar(32) | 必填，无默认 | 外部系统管理员账号 |
| `updated_by` | varchar(32) | 必填，无默认 | 最后维护管理员账号 |

优先级初始 NORMAL，仅 SUBMITTED 可由范围内客服修改。acceptance_due_at 按 created_at 和新优先级重算，已登记的 acceptance_overdue_recorded_at 保留。更新与 PRIORITY_CHANGED 事件同事务。首次接单或分派时若已超过期限且未登记，则同事务补记超期。CHECK约束onsite_eligible只能在PROCESSING/WAITING_CUSTOMER且service_item_id、service_area_code、service_location非空时为true；用例核对受理快照的现场能力。解决、取消和撤回资格时复用预约取消用例。

support_context使用固定schema_version和具名字段：os_name/os_version、software_name/software_version、connection_type、error_code、affected_scope及field_sources；connection_type限定USB/LAN/WIFI/VPN/OTHER/UNKNOWN，affected_scope限定SINGLE_USER/MULTIPLE_USERS/UNKNOWN；名称/版本/错误码各至多100字符。schema_version及field_sources由后端构造，前端不能伪造工具/资产来源。枚举、版本依赖名称及文本预算由用例校验，不提供任意JSON配置。环境文本不含凭据或全量网络配置。分类/环境可由范围内客服或当前处理人带版本更新，写CONTEXT_UPDATED；改变项目先核验新开通资格，原快照留在事件。现场信息修改必须无活动预约。

resolution_type、resolved_at及confirmation_due_at在RESOLVED/CLOSED同时存在，其余为空；closure_reason当且仅当CLOSED存在。RESTORED只表示人工报告恢复，CONFIRMATION_TIMEOUT不解释为客户确认。REFERRED转介要求公开原因及去向，新提交的未分类问题只允许转介处理结果。LEGACY_UNKNOWN只用于迁移旧记录且service_scope_snapshot.origin=LEGACY_MIGRATION，API不接收；原始旧事件及迁移依据保留，不能为了满足CHECK编造处理结果或客户确认。

动作按row_version、状态和处理人条件更新，工单、事件与相关站内通知同事务。customer_id、requester_id、assignee_id 对身份服务是逻辑引用。按 (requester_id,customer_id,updated_at DESC,id)、(customer_id,status,created_at,id)、(assignee_id,status,updated_at,id) 建立查询索引。期限扫描使用 (status,acceptance_overdue_recorded_at,acceptance_due_at,id) 与 (status,confirmation_due_at,id) 复合索引，分别限定 SUBMITTED 且未登记超期和 RESOLVED。

工单等待字段成组约束：wait_reason/follow_up_at当且仅当两类等待非空，退出等待清空当前字段但保留事件；wait_cycle非负，等待时为正，follow_up_notified_at仅当前等待可有值。索引(status,follow_up_at,id)支持跟进扫描，SYSTEM提醒事件元数据含wait_cycle，同锁重核仅提醒一次。诊断上下文版本与行版本分别非负；所有事件锁工单递增event_sequence，不再使用MAX(sequence_number)+1。所有正式用户动作在同一事务写sd_action_receipt；系统期限事件不伪造用户回执。

storage_key、(created_by,client_upload_id)、(series_id,revision_number) 和 (id,series_id) 唯一，修订号为正。上传前先在当前权限内查询请求回执；同键同摘要返回原修订，同键异义冲突。knowledge先以Redisson按created_by+client_upload_id互斥外部上传，取锁后重查回执；锁在数据库事务外取得且不替代权限核验。并发上传、锁失效或旧请求迟到在提交修订时仍由唯一约束收敛到一个结果，失败事务不占用修订号；未被采用的 OSS 对象进入受控孤立对象对账，不承诺外部存储恰好一次。上传回执未查到只表示尚未看到已提交修订，不能断言 OSS 没有在途写入。Bucket、Object Key 和 Version ID 创建后固定，由知识服务校验允许的环境与长度；不持久化 endpoint、临时签名 URL 或访问凭据。SHA-256 来自真实文件字节，OSS ETag 不作为 SHA-256，也不假定所有上传方式的 ETag 都等于 MD5。系列内 PUBLISHED 与 DISABLED 合计最多一行，由 current_series_id UNIQUE 保证。DELETED 与 deleted_at 对应。published_at、published_by 同空同有，PUBLISHED、DISABLED、RETIRED、WITHDRAWN 必须有已发布标记、当前任务及来源复核记录。索引提交/取消事务状态来自Java业务任务，受理及执行状态经AI RPC查询，不伪造统一发送态。

current_job_id仅允许DRAFT在前次submit_state=ABORTED，或前次提交已COMMITTED且AI终态/解析收敛后切换；前次SUBMIT/CANCEL仍PREPARING或AI结果未知不切换，首次准备同样锁文档登记；已发布修订不新建索引尝试、不取消其成功任务，也不修改已有片段。新的解析/切片/向量空间通过新 DRAFT 修订重新验证与发布，同空间副本重建沿用旧片段身份。

发布和恢复先核对 AI 成功任务和片段，再锁系列、修订与当前Java任务，比较row_version/current_job_id，submit_state须COMMITTED、cancel_state为NONE或ABORTED，AI lastCommand须SUBMIT。替换时先退役旧修订，再发布同系列的较新修订，并追加两条相关事件，整个动作一次提交。replaces_document_id 非空唯一，禁止自指。前驱须为切换前的PUBLISHED/DISABLED或最近已发布的WITHDRAWN版本且修订号较低。已发布资料的原件和适用范围固定，变更通过新修订。适用规则变化需要管理员确认差异并在事件留痕。

停用保留该系列的当前修订位置。恢复只作用于当前 DISABLED 修订。删除仅用于从未发布的DRAFT；从未建索引可直接按版本删除，有索引尝试则须各尝试submit_state=ABORTED，或取消已COMMITTED且AI lastCommand=CANCEL、任务终态/解析收敛；保留业务事务事实及取消墓碑，不能以AI NOT_FOUND证明无在途消息。并须确认无活跃索引、无SUBMITTING/ACTIVE/UNKNOWN远端解析；有未收敛任务时先取消和对账，已发布资料通过停用或替换退出检索，指定 OSS 对象版本与历史引用保留。管理列表按系列和修订号查询，检索授权从服务项目及适用规则反查后筛选PUBLISHED及受众。失败草稿或孤立对象回收先核查记录、任务、引用和在途提交；版本控制不代替备份，生命周期规则不得提前删除被引用版本。不建立自动物理删除任务；孤立对象物理回收在暂停上传并核对在途提交收敛的运维窗口执行，不仅凭对象年龄判断。

知识风险撤回WITHDRAWN不占当前系列位置，后继发布仍可replaces_document_id指向最近已发布且被撤回的修订，锁系列核对修订递增；REVOKED独立于发布态，新召回及历史读取都拒绝。恢复ALLOWED只恢复访问，不恢复WITHDRAWN执行资格。access/withdrawal原因、操作者及版本变更同事务记kb_document_event。


规程定义与原件一并创建，upload_request_hash同时覆盖其规范摘要。仅TROUBLESHOOTING_GUIDE允许非空定义，由系列类型在用例中核验；其他类型五个规程字段均为空。定义不提供原地编辑，纠错创建新修订；草稿校验只更新验证标记及row_version，并追加带动作键的文档事件，原回执查询先于状态/版本判断。定义存在时发布必须核对验证摘要等于当前摘要、全部定位属于本修订、所需原件证据已核对；已发布后这五列固定。不设独立规程/步骤实体或发布状态。案例由知识管理员人工编写Markdown草稿，source_review_note记录脱敏核对人、确认时间、材料使用依据和结论来源；不保存私聊或原工单访问凭据，不另建候选审批链。

## 23. `desk_knowledge.kb_index_job` 索引尝试与事务事实

(document_id,attempt_number)、(id,document_id)、(requested_by,client_request_id)唯一。业务任务是管理回执、尝试身份和事务事实，不是outbox；没有delivery_status、自动重发次数、next_attempt_at或发送领取字段，不建立定时发送器。client_request保存原document_id、row_version及处理配置，同请求键先比原输入再返回原状态；command_input保存已分配jobId的不可变输入，与MQ的requestHash核对。信封输入对同jobId固定，SUBMIT operationId=id，CANCEL operationId=cancel_operation_id；浏览器只能提供幂等键，不能指定服务器jobId。

准备登记短事务锁文档→本地任务，核对DRAFT及前次收敛，保存PREPARING、UTC截止及current_job_id并递增文档row_version，确认阶段沿用准备提交后的版本。准备不等于业务已接受，重复同请求只返回原进展，不重复发送。半消息在事务外发送；明确取得半消息回执后，确认事务重新按文档→任务锁定并另取MySQL UTC时刻，仅在当前版本/任务匹配、PREPARING且决策时刻未过截止时提交COMMITTED和对应资料事件。数据库锁不跨网络，MySQL COMMITTED后才向Broker COMMIT；二次确认失败不能反向改ABORTED。

CHECK限定submit_state的有效字段组合，PREPARING→COMMITTED/ABORTED单向迁移由条件更新保证；submit_deadline_at>created_at，提交时间不早于created_at。允许确认事务在截止前取得决策锁、截止后才完成提交，其他回查/收敛操作必须等待同一行锁，不能仅按墙钟推翻已开始的确认。SQL事务总预算5秒、锁等待有界，knowledge连接另设服务端空闲上限及失效检查，参数见部署说明；应用暂停时不能无限持有决策锁或在Broker回查耗尽后迟到提交。准备过期的收敛事务以同一文档→任务锁序更新PREPARING→ABORTED，提交后回查才能ROLLBACK，恢复的旧请求不再有提交资格。

cancel_state=NONE时cancel_operation_id/cancel_requested_by/cancel_deadline_at/cancel_committed_at全空；非NONE要求前三者非空，且submit_state=COMMITTED；cancel_committed_at当且仅当取消COMMITTED非空。首次取消NONE→PREPARING，随后COMMITTED或ABORTED；仅ABORTED可读取最新文档版本后显式再准备并替换cancel_operation_id，已COMMITTED不回退或覆盖。取消PREPARING禁止发布/切换尝试，确认事务同样重核DRAFT、当前任务、准备后的版本及截止，并原子写取消提交时刻和INDEX_CANCEL_REQUESTED事件。所有SUBMIT/CANCEL准备、确认及终止均在同一事务递增文档row_version；既有提交/准备先返回原回执，新操作再校验版本，阻止旧取消请求自动开启新操作。对旧取消operationId回查，若与当前不符则证明旧操作未提交，可ROLLBACK；已提交取消不替换ID。

TransactionChecker匹配jobId、输入摘要及operationId；已COMMITTED→COMMIT，已ABORTED→ROLLBACK，PREPARING未到期/数据库失败/锁等待→UNKNOWN。查不到预登记业务记录属异常，不能因一次未见就猜ROLLBACK。历史SUBMIT提交证明不会因当前任务已取消、已换版或终态而失效；重放已提交原指令只依赖已有提交事实，不重复业务变更。业务证明保留到所有可能回查/重放和历史引用结束，默认不物理删除。半消息超预算或Broker数据丢失不由本表自动投递，管理员核对后沿原身份受控重放。

索引提交202只在本地COMMITTED后返回。半消息失败/未知且本地未提交时返回失败/未知，原键查询PREPARING/ABORTED；同键ABORTED不复活，新业务尝试才分配新clientRequestId/jobId。AI受理/执行事实不复制进本表；GetStatus核对摘要/lastCommand。仅本地SUBMIT提交、无准备中/已提交取消、AI成功及远端收敛才能发布。以(submit_state,submit_deadline_at,id)、(cancel_state,cancel_deadline_at,id)索引有界收敛过期准备；没有AI任务的ABORTED尝试也可安全结束，不凭不存在的远端任务等待。

任务ID与Java索引尝试kb_index_job.id一致。(id,document_id)唯一供片段复合FK，(document_id,attempt_number)唯一，active_document_id UNIQUE限制每文档至多一个QUEUED/RUNNING。以(status,created_at,id)领取任务，(status,claim_until,id)恢复过期执行权。MQ相同jobId同request_hash幂等受理，不同输入记协议冲突并进入有界重投/死信，不ACK为成功。取消先到用完整输入写CANCELLED墓碑和last_command=CANCEL，晚到SUBMIT只保留原结果。活跃任务取消原子清空执行权并写终态；已终态保留原状态同时记录last_command=CANCEL，重复不重置阶段或started_at。受理事务提交后才ACK；AI进程仅通过IndexJobService/GetStatus提供内部任务查询。CANCELLED要求last_command=CANCEL；last_command=CANCEL不要求执行终态一定是CANCELLED，因为成功/失败可能先提交。

MinerU 和 Embedding 在事务外。调用 MinerU 创建前持久化 SUBMITTING，收到已知远端 ID 后持久化 ACTIVE，确认远端已终止后记 SETTLED。创建结果未知且无 ID 时记 UNKNOWN。MARKDOWN使用NOT_REQUIRED且无远端ID，不调用MinerU；PDF使用NOT_SUBMITTED/SUBMITTING/ACTIVE/SETTLED/UNKNOWN。NOT_REQUIRED、NOT_SUBMITTED或SETTLED表示无未收敛远端执行。仅PDF的SUBMITTING/UNKNOWN且没有远端ID时，受控运维命令须确认旧解析环境已隔离且不会恢复，才可写parser_reconciliation并改SETTLED；MARKDOWN始终NOT_REQUIRED，不走该对账。SUCCEEDED要求started_at、两路索引验证，且PDF为正page_count及SETTLED，MARKDOWN为page_count/远端ID均空及NOT_REQUIRED；格式与字段组合由CHECK保护。在有界本地事务内一次固定完整切片清单及稳定 ID，并由 CHUNKING 进入 EMBEDDING；不能把部分已存片段当作完整解析。超出页数、片段数或事务预算时明确失败。索引外部写入前持久化 INDEXING 阶段。向量在事务外由百炼生成并写入 Qdrant，关键词写入 ES；按 job_id 核对两路完整LEAF片段 ID 集合、数量、载荷和查询可见性后，才条件提交 SUCCEEDED。任一路失败都不得发布；重启先检查已有条目，只补缺失或不匹配的批次，同 ID upsert，不重新解析。Qdrant 已有向量可复用；尚未持久化的 Embedding 结果可能需再次付费生成，不能承诺跨库恰好一次。取消或迟到索引回执不能将任务置为成功，迟到副本因无成功授权任务不可被召回。RUNNING 要求 started_at 与 stage，finished_at 当且仅当终态有值，FAILED 要求 error_code。取消后的迟到回执可用于清理远端任务，不能写片段或改变本地终态。发布状态由 knowledge 决定。

RUNNING 当且仅当 claim_token、claim_until 非空；QUEUED 与终态清空执行权。worker 在短事务中从 QUEUED 领取，或者比较过期租约接管 RUNNING；续约、阶段、片段和成功提交均须匹配当前令牌及有效租约。取消与失败终态同步清空执行权，旧 worker 不能覆盖新领取者或终态。恢复时，PARSING 沿原 MinerU 标识查询；SUBMITTING 且无远端 ID 按 UNKNOWN 对账，不重新创建；切片清单已固定时只补齐已有 ID 对应的外部副本。已取消任务的远端回收按 parser_state 和原任务身份单独对账，不能复活本地任务。租约不代表远端进程已停止。

(index_job_id,chunk_number)、(id,index_job_id)唯一，chunk_number正数。父片段必须同任务且先于子片段，禁止自指/循环，最大深度8；由固定清单构建和用例验证。叶片按chunk_number定位相邻关系，无需双向next/previous冗余列。SECTION可包含最多48KiB正文，超出拆为有完整性标记的连续单元；展开不能丢失前置条件。数据库约束来源JSON为带版本对象且kind与任务格式一致（跨表一致性由用例检查）；PDF含非空pages（page_number、可空printed_page_label），MARKDOWN含非空segments（anchor、line_start、line_end）。用例核对正序、不重叠、真实页界/行界和UTF-8原件，文本不伪造页码。向量数量、维度、有限数和非零分别校验，同维度不同模型按空间版本隔离。

使用 (index_job_id,chunk_number) 唯一索引和 (document_id,index_job_id) B-tree。MySQL 保存正文、来源、任务和历史引用事实，不再保存 embedding 列。ES 的文档 ID 为片段 ID，保存受控关键词副本；Qdrant 的 point ID 由同一 32 位 ID 无损转换成带连字符 UUID，payload 保留原始 chunk_id、index_job_id、document_id 和 vector_space。原始 ID 与 point ID 一一对应，不随机生成第二个片段身份。

Qdrant 初始 collection 为 desk_chunks_{env}_te4_1024_v1，向量配置 size=1024、distance=Cosine，向量模型及预处理空间版本固定在任务 processing_config。为 index_job_id、document_id、vector_space 创建 keyword payload 索引。通过 HTTPX 调用 REST，批量 upsert 使用 wait=true，并核对已完成响应及实际查询可见性；超时按原 ID 对账后重送。查询使用 /collections/{collection}/points/query，filter.must 限定授权 index_job_id 集合与 vector_space，params.exact=true，固定使用精确召回。Qdrant 不负责调用模型。

知识服务返回的当前修订及任务是授权依据；payload 不能成为权限事实。两路均在查询前过滤，融合后按 ID 批量回查 MySQL 核对任务、文档及正文，交付前重新核验知识发布版本。空授权不发无过滤查询。ES 可直接按 MySQL 片段重建；Qdrant 优先使用完整 snapshot 恢复。没有可用向量快照时，需要按原模型空间重新调用 Embedding、校验费用预算与效果；供应商模型不可用或空间改变时走新任务和知识版本复核，不能假定从 MySQL 零成本恢复原向量。更换模型、维度或预处理必须建立新 collection，并在受控重建和知识任务切换完成后统一更新查询配置；不混用新旧空间。

BOOK_ONSITE草稿只允许CUSTOMER_SELF_SERVICE拥有者，并以已查询到的CREATE_TICKET回执关联handover_ticket_id；即使诊断任务为HANDED_OFF，仍可基于已确认事实生成预约草稿，但不重开诊断Run。预约目标必须为本人原客户工单，当前现场资格/地点/版本从ticket查询，不能从旧任务快照推断。ADD_RECORD/RESOLVE_TICKET/REQUEST_INFORMATION只允许TECHNICIAN_ASSIST且执行时核验当前处理关系。技术人员可提出预约建议，但不能以技术草稿代替客户确认。

JSON内的ID不能由FK直接保证，所属用例在同任务/修订锁内验证存在性、范围、版本及来源，不存在的事实、假设键、来源号或规程检查键直接拒绝。假设无需全库反向查询，事实变更时在同任务有界投影内失效；摘要依赖由ai_source_usage关系行承载，历史回答读取检查全部实际来源。快照不能用于跨客户检索或授权缓存。字段长度同时受UTF-8字节预算约束，超限拒绝并要求缩小输入，不静默截断。


规程schema固定：check_key为修订内唯一稳定代码；risk_level仅LOW/HANDOVER_REQUIRED，客户不能执行后者；roles仅CUSTOMER/TECHNICIAN。required_fields取support_context白名单，prerequisite_check_keys只能引用本定义较早检查；完成前提须有同环境有效反馈且execution_status=PERFORMED或工具真实观测。prerequisite_answers只约束已声明前置中的CHOICE检查，allowed_values至多20项且必须属于其原选项；所有条件均匹配实际规范答案才能继续，OBSERVED_DONE也不能豁免答案值核对。缺省空列表兼容原执行前置语义；补充条件使用新知识修订，不回写旧定义或增加业务表/列。stop_conditions/handover_conditions为固定条件码列表：SAFETY_HAZARD_REPORTED（用户报告冒烟、异味等风险）、DATA_LOSS_RISK_REPORTED、ADMIN_PRIVILEGE_REQUIRED、OUT_OF_SERVICE_SCOPE、NO_PROGRESS_LIMIT、EVIDENCE_CONFLICT；仅由宿主规则/明确用户反馈触发，模型不能覆盖已触发条件。每类最多10项，不接收谓词脚本或任意表达式。关键风险未知先澄清，不默认安全。

人工CHECK答案除answer_schema定义的value外，必含execution_status=NOT_PERFORMED/PERFORMED及outcome=UNKNOWN/UNCHANGED/IMPROVED/RESTORED_REPORTED；NOT_PERFORMED时outcome只能UNKNOWN，不能据“已回答”满足检查前置。CLARIFICATION只保存规范value，无伪造执行状态；工具观测结果按只读工具schema验证。answer_schema与normalized_answer各最多8KiB，选项至多20项，文本值至多2000字符，拒绝额外字段；公开JSON显式转成lowerCamelCase。

运行中的诊断写工具只生成有界提议，实际检查、事实、假设及草稿在最终事务中按conversation→task→run及原input_state_version一次校验、写入并分配一个新task_state_version；任务事件记录全部变化。失败/取消Run不得留下可操作待答项或PENDING草稿；调用账目及实际来源仍保留故障证据。纯只读工具观测也须在成功最终事务中转为领域事实，不能越过执行令牌。无模型的人工事实/草稿用例走各自任务事务。任务详情及事件中的派生假设按proposed_run_id核验全部实际来源，撤权后只返回安全状态与原因，不能通过事件绕过回答隐藏。

锁序：user为服务商组织→账号/角色；ticket创建为项目→资格→设备→新工单，已有分类先项目/资格后工单，其余工单→预约→时段；knowledge为系列→修订→索引尝试；AI受理为execution_gate→conversation→task→run→check/call，其他任务动作从conversation开始。查询回执在当前权限内先行。不得在持有数据库锁时调用HTTP/RPC/模型/OSS，远端校验与本地提交的时间窗口在交付及动作采用重新复核。

AI worker按状态索引有界SELECT FOR UPDATE SKIP LOCKED领取，再条件设置令牌/租约；不使用MySQL不支持的UPDATE RETURNING。续约和提交同时匹配当前状态、令牌、未过期租约；取消/终态清空执行权。死锁只在无外部副作用的完整短事务内有限重试，不重放整个付费调用。

可空STORED唯一生成列均用CASE WHEN指定活动状态 THEN目标ID ELSE NULL END，普通UNIQUE允许多个NULL：组织provider_guard、文档current_series_id、索引active_document_id、预约active_ticket_id、任务active_conversation_id、运行active_conversation_id/active_task_id。CHECK显式检查NULL组合，复合FK引用完整UNIQUE，循环引用先建表再ALTER，不关闭foreign_key_checks。新表所有PK、ID、状态、摘要、布尔、时间和正数约束遵守第1节。跨表角色/同任务/检查前置关系不能宣称由单列FK保证，列出的用例约束必须有并发与反例测试。

工单、事件、正式回执、知识发布依据默认长期保留；私有会话逻辑归档不承诺物理擦除。附件retain_until是可清理条件而非自动删除许可；有未收敛调用/引用/保留依据不得删除。摘要可失效重建，原始来源不可提前删。受控物理清理先暂停相关写入、核对引用与在途、形成最小墓碑和备份，再逐项清理；运行日志按部署有界保留，不充当业务审计。生产需按实际数据约定批准保留策略，未批准不启用批量清理。

恢复联合保存四库、事务消息事实/墓碑、OSS知识及附件版本、Qdrant快照和模型空间；ES可由LEAF片段重建。恢复不让UNKNOWN自动付费重跑，不把数据库恢复当成外部动作撤销。真实MySQL验证生成列、CHECK、复合FK、索引查询、锁竞争及重复取消，替身/SQLite不计通过。MySQL DDL隐式提交，设计完成不代表迁移已执行。
